### Controls

- <a id="d-2026-11-09-a-cinematic-can-t-be-interrupted"></a>**2026-11-09, a cinematic can't be interrupted by accident** (owner, after the quarry lever's gate shot ended as it began on desktop: "the cinematic should be uninterruptible unless by maybe a specific highlighted button press"). No key, click, tap, wheel, mouse move, pad button or stick ends a camera pull-out (the lever and summit-switch gate shots, the Works throat, Place's celebrations). - <a id="d-2026-11-09-a-world-reset-starts-the-game"></a>**2026-11-09, a world reset starts the game over** (owner: "upon world resets, if I log in it shouldn't spawn me in town, it should start me at the beginning of the game with the character creation menu I believe"). The first load after a `WORLD_NS` bump is a first visit: the fall, then the name-and-colour card, landing on the shore rather than at the village spawn. The card comes pre-filled with the saved name and colour, so a reset costs one Jump in; what the reset already forgets (room progress, the railway wardrobe, reward claims, The Boogler) is unchanged, and identity and preferences stay. A reload after that, or any load without a reset, is a returning visit as before. Built in `src/player/world-reset.ts` (`newWorld`) and `src/player/arrival.ts`; [first-run](game-design/first-run.md#existing-arrival). The open calls it left are in [agent-calls](agent-calls.md).
- <a id="d-2026-11-09-a-room-reset-starts-the-game"></a>**2026-11-09, a room reset starts the game over too, The Boogler included** (owner, on an operator `reset` still landing them in town: "yes"; "room reset should also wipe boogler memory, he's just another NPC"). Resetting one room (`npm run server`) is a new game for that room's players: the fall and the card on their next join, with that room's local progress, wardrobe and reward claims forgotten, and The Boogler's memory with them even though it is shared across rooms. Other rooms' progress, identity and preferences stay. A restore brings the backup's world back under its own id, so it starts over only the browsers that joined a different world in between (undoing a reset is seamless for everyone who did not play the reset room). Built on a per-room world id from the server (`born` in `welcome`, `server/src/store.ts`) and `src/features/room-reset.ts`; [first-run](game-design/first-run.md#existing-arrival).
