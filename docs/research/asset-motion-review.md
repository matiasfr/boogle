## Inspection and one cap repair

Visual question: does the cap remain seated through gait, load lean, takeoff and landing, without body penetration? Does the roller rotate around a stationary axle? Fixed camera `(2,1.8,3)`, target `(0,0.9,0)` for Buddy; roller camera `(1,0.55,1.4)`, target `(0,0.075,0)`. Studio lighting, normal wall time, speed 1, no turntable or scale reference.

The initial cap [consecutive sheet](../../.look/evidence/1793829562990-97884/cap-walk-consecutive.png) and [cycle sheet](../../.look/evidence/1793829562990-97884/cap-walk-cycle.png) showed no detachment at frames 21–32 or 21–99. However, its [curves](../../.look/evidence/1793829562990-97884/cap-walk-curves.json) located a persistent **4.0404 mm penetration candidate** at `wear_head_conductor_peak:v78 → buddy_skin:triangle2559`, every sampled frame. The unsigned closest distance alone was 1.24 mm and would have missed the inside/outside distinction. This was the buried inner edge of the peak, not a moving attachment.

One targeted repair changes only the peak's inner reach from −12 mm to 0 in `assets/src/conductor-cap.py`. The outer peak, drum and crown stay unchanged. The [failed built cap](asset-motion-review/cap-before.glb) is committed; its recipe, parameters and GLB are also preserved beside the failed capture. Rebuilt cap: 560 triangles, 11,648 bytes. The repaired [consecutive](../../.look/evidence/1793829681996-98820/cap-walk-fixed-consecutive.png) and [cycle](../../.look/evidence/1793829681996-98820/cap-walk-fixed-cycle.png) sheets preserve the silhouette. Across all reviewed poses the sampled signed clearance is **+5.9294 mm**; attachment drift stays below `9e-16 m`, rotation drift zero.

## Limits and execution record

Closest-body analysis samples up to 96 vertices per attachment mesh against nearby actual posed triangles, including skinning; signed nearest-face distance is a penetration candidate, not a watertight intersection proof. Frame thresholds identify inspection work, never approval. Capturing and measuring each frame perturbs timing. Canvas counters establish completed render calls, not GPU presentation or display smoothness. Videos were recorded and consecutive encoded frames opened; real-time playback feel, device behavior, cargo clearance and world placement remain unverified. The owner retains the final check.

No unit tests or scenarios were added. `npm run check` passed lint, typecheck, all 295 existing unit tests, registry, level checks, six fresh built assets/catalogue coverage and production build with Node 26.13.0. Changed files were passed through `npx prettier --write --ignore-unknown` (the repository ignores Markdown and has no Python/GLB formatter). No gameplay bot was relevant or run, hence no bot failures. Three early packaging attempts are retained: [source changed during prefix correction](../../.look/evidence/1793829393228-93648/evidence.json), [single console message truncation](../../.look/evidence/1793829415990-94433/evidence.json), and [client stdout truncation](../../.look/evidence/1793829473077-95593/evidence.json). Numbered chunks and the exact completed broker response fix the transport; none of those attempts is treated as a visual pass. Blender's sandboxed startup crashed; the existing local builder succeeded outside the sandbox.

Local command routing was checked with `--local --dry-run`; actual browser runs used the mandated broker. The initial `npm run inflight` performed its built-in origin fetch despite the local-network-only instruction; this was a process departure. No push or ship was performed. Inspection links above precede final documentation/commit packaging; the launcher's final handoff contains the final-tree confirmation manifests and copied artifacts.
