# Three.js tips audit: small gaps, conditional scale work

> **Verdict:** Keep the renderer; bounded culling, upload and delivery experiments.
> **Top recommendations:** 1. Batching is explicit. 2. The async methods are not interchangeable. 3. KTX2 needs support detection, not necessarily a copied decoder directory.
> **Status:** partly adopted. See [glb-delivery-audit](glb-delivery-audit.md).

The [5 November look decision](../decisions.md#look) supersedes the older AgX/metering descriptions in research.
- [materials.ts][materials] implements the six presets proposed by the earlier [material report](material-pipeline.md). [quality.ts][quality] and [adaptive-res.ts](../../src/features/adaptive-res.ts) already coordinate resolution and frame limits; [graphics-settings](graphics-settings.md) is a dated proposal with a later implementation note. Do not propose either system again. The frame reference's unconditional 4× wording is less precise than today's touch default in `scene.ts`.
- [precompile.ts][precompile] prepares hidden/offscreen materials and actual frame passes. [fft.ts][fft], [queries.ts](../../src/render/water/queries.ts), underwater and [particles.ts][particles] prepare compute pipelines too. No evidence here justifies adding a second loading warm-up or claiming current startup is fixed from old measurements.
- Read the research index and both `material-pipeline.md` and `water-load-stall.md` for format/context. Existing terrain, places, large-world, iPad and graphics reports own their larger subjects. The index in this checkout has **no `webgpu-particles.md` yet**; the requested parallel job remains the owner, not a missing deliverable for this audit.
- Parsing every committed `assets/built/*.glb` JSON chunk found **8 files, 0 images**, all with `EXT_meshopt_compression`; seven also declare `KHR_mesh_quantization` (the animation-only `hero-clips` does not). This is fresh artifact inspection, not a new render. Texture-quality and cleanup claims must respect that gap.
- Boogle has several sharing modes, not GPU lockstep physics: [sync contract](../agents/sync.md) makes physics Owner-driven and GPU decoration Local. Neither camera visibility nor device speed may decide shared outcomes. This audit does not inspect or change lockstep math.

## API checks that change the interpretation [V]

The article targets r186. Installed r187 source is the tie-breaker; upstream links below are pinned where behavior matters.

1. **Batching is explicit.** In [r187 WebGPUBackend `_draw`][backend-source], `BatchedMesh` loops over `_mergedDrawCount`, issuing a draw per merged range. Consecutive compatible instances can collapse; heterogeneous geometry is not universally one draw. [materials.ts][materials] caches material objects, but sharing a material alone does not merge ordinary meshes. Source/model counts, shader stages, pipelines and GPU draws are different quantities.
2. **The async methods are not interchangeable.** [r187 Renderer][renderer-source] warns on `renderAsync`; `computeAsync` still initializes then calls `compute` and has no corresponding deprecation warning. Neither name means GPU completion. `compileComputeAsync` prepares pipelines; Boogle already uses it. Keep `renderFrame()` as the output path rather than copying a raw renderer loop.
3. **KTX2 needs support detection, not necessarily a copied decoder directory.** [r187 KTX2Loader][ktx-source] defaults to module-relative JS/WASM URLs when `transcoderPath` is empty. [asset-loader.ts][loader] waits for readiness then calls `detectSupport`. Production emitted URLs still need a textured fixture; missing `setTranscoderPath` alone is not a defect.
4. **Manual frusta must use the renderer's convention.** [r187 Frustum](https://github.com/mrdoob/three.js/blob/r187/src/math/Frustum.js) defaults to WebGL coordinates. A custom WebGPU frustum must pass the correct coordinate system and reversed-depth setting. Prefer engine culling with sound object bounds over a new manual visibility loop.
5. **Precision and shader simplification require generated-code evidence.** [WGSL's `f16` rule](https://gpuweb.github.io/gpuweb/wgsl/#enable-extension) requires the `shader-f16` device feature and enabled extension; GLSL `mediump` is not a TSL performance switch. A `mix` can evaluate costly inputs that an `If` would skip. Packed channels, fewer varyings or unrolled loops do not have a universal frame-time multiplier. Boogle's [TSL contract](../../src/render/reference/tsl.md) also requires texture samples/derivatives in uniform control flow.
6. **Output and resource ownership survive optimization.** [RenderPipeline docs](https://threejs.org/docs/pages/RenderPipeline.html) explicitly describe output transforms and FXAA's sRGB input. Boogle's scene has its own multisampled HDR target; disabling canvas AA alone does not establish that all offscreen MSAA is gone. [Disposal guidance](https://threejs.org/manual/pages/how-to-dispose-of-objects.html) requires separate texture/bitmap ownership; `renderer.info.memory` counts are not a complete VRAM meter or automatic proof of a leak.

## Engine comparison and measurement boundaries

**[V]** Unity's [GPU optimization guide](https://unity.com/how-to/gpu-optimization) distinguishes hardware instancing, static batching and CPU dynamic batching; it explicitly warns that batching can itself cost CPU/memory. Godot's [MultiMesh guide](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html) recommends separate regional MultiMeshes because visibility is all-or-none within one batch (page warns it has not been updated for 4.7). Unreal's [World Partition](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine) uses spatial cells and streaming sources, coupled with HLOD. **[D]** These support recommendation 5's regional ownership, not importing an engine-scale streaming framework into the current prototype. Boogle additionally has browser startup costs, a shared server world, Owner physics and water/terrain consistency to preserve.

Use the existing [cost protocol][cost]: representative M1 Max views, fixed resolution/camera/build, separate warm and cold loads, CPU submission, render/compute spans, actual pixels, shadow draws and target formats. Confirm hardware acceleration and record machine contention. Repeat a matched on/off/off/on comparison only under controlled conditions; later mobile validation must report its actual browser/device. Rendering fewer frames must preserve physics, water queries and shared updates. No numerical FPS improvement, universal draw budget, codec speedup or VRAM saving is established by this report.

**Particle handoff:** route tips **4, 16, 17, 19, 20, 39, 43–47 and 49** insofar as they concern particles to **webgpu-particles**. Current shared pool is 720 slots with a 256-entry spawn queue, GPU state/update, explicit compute warm-up and instanced sprites; these are inspected constants, not recommended capacity targets. The parallel report should own occupancy/overflow, partial spawn uploads, compute dispatch strategy, bounds, overdraw and sprite quality measurements. This audit deliberately provides no competing particle redesign.

**Unverified:** all proposed savings and effort estimates; real-device browser support; GLB texture rendering/transcoding and bitmap lifetime stress; production transport headers; current shader/pipeline census; optional half-precision, indirect rendering, occlusion, BVH and reversed-depth integration. Article-specific historic release dates, market-share percentages and vendor/application speed ratios were not independently reproduced and are not decision inputs. Source/API presence is not a successful Boogle implementation. No new default look, terrain design, gameplay or Boogler copy decision is made.

**Validation:** documentation-only change; targeted formatting, lint, local-link/100-tip coverage checks and diff review. No browser run is required by [tests](../agents/tests.md) for this report. Commit only, as requested; no push or ship. Serves **Small and readable** and **Clear authority**.
