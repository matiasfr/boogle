# Reviewing agent-built Boogle

> **Verdict:** Review loop first: one link, before and after, a pinned note, the right agent.
> **Top recommendations:** 1. Agent submits evidence: record review ID, job/topic and launcher checkout, source tree/build, asset hashes, baseline. 2. Owner taps the image: capture normalized image coordinates plus frame/time and text. 3. Feedback arrives durably: extend the existing report path with versioned review records, IDs.
> **Status:** partly adopted. See [plan review-inbox](../plans/review-inbox.md), [plan asset-stage](../plans/asset-stage.md), [plan look-compare](../plans/look-compare.md).

_2026-11-03. Research, not implementation approval. **[V]** = primary text or code read; **[A]** = indexed excerpt/abstract only; **[S]** = secondary account; **[D]** = recommendation/inference. Local audit: `993416e2`; sibling Dev-menu checkout: `dfc8d8b6`, unshipped status supplied by the brief, deployment not checked. No game/device test or performance measurement._

**Build a review loop first: one link → before/after → a pinned note or decision → the right agent → a revised comparison.** Next, give assets their own stage; then make the Dev shell persistent and non-modal, with free camera and a shared-HDR grade board. Keep the already-researched [eight-tool menu](dev-menu-plan.md); this report extends its review workflow, not its cheat inventory. Serves **Understandable at a glance**, **Show, don't tell**, and **Small and readable** in [DESIGN.md](../../DESIGN.md).

## The agent-to-owner-to-agent loop

**[V] Existing pieces:** [look](../../dev/look/look.ts) captures stills/motion/curves and [before-after](../../dev/look/before-after.ts) pairs builds; [clip](../../dev/video/clip.ts) records scripted footage and [reel](../../dev/video/reel.ts) edits it. Scripted smooth footage does not prove real-time performance. [/protos](../../protos/main.ts) and the [prototype bar](../../src/proto/bar/index.ts) already ask one gut question. [send.ts](../../src/proto/bar/send.ts) sends verdicts to `/report`; [verdicts.ts](../../scripts/verdicts.ts) retrieves them. A queued beacon currently counts as sent, not server-acknowledged. [Atlas](../../dev/atlas/cli.ts) explains architecture; it is not an art-review inbox. [Codex's broker](../../dev/codex/README.md) already preserves source fingerprints, captures and named follow-up sessions. These are the foundation.

**[D] A review card needs one question, one sentence of change, baseline/candidate images or a short synchronized clip, and Accept / Changes / Can't tell.** Technical diagnostics stay collapsed. The browser card and agent command must invoke the same bounded handler, with JSON availability, arguments, result and snapshot; retain the sibling menu's `boogle.dev.run` approach. A reproducible link names a versioned review record, not arbitrary JavaScript or a mutable `main` URL pretending to be an old build.

1. **Agent submits evidence:** record review ID, job/topic and launcher checkout, source tree/build, asset hashes, baseline, route/fixture, camera/FOV, clip/time or frame+FPS, lighting/grade/exposure, viewport/DPR and checks. Publish retained media with the record: `.look/` paths alone are not phone-accessible. Do not assume old Vite-hashed files survive deploys. Existing `before-after` shares current dependencies with its archived source; old-lockfile comparisons require separately installed matching dependencies before claiming exact-build reproduction.
2. **Owner taps the image:** capture normalized image coordinates plus frame/time and text; optionally include stable asset/node/bone ID or world position. Keep the original image pin even if geometry changes. Example: “heel penetrates floor” at `buddy / Jog_Fwd_Loop / 0.42 s`, with the retargeted pose and camera. A range comment covers a bad transition. A live-world report freezes evidence, not the multiplayer room.
3. **Feedback arrives durably:** extend the existing report path with versioned review records, IDs, acknowledgement and retry/deduplication; distinguish Pending from Received. Keep local draft/download fallback. Add machine-readable retrieval to `npm run verdicts`; its present output is text/Markdown, not a review-task API. Authentication and attachment storage need an implementation plan; never embed the report-reader token in a review page.
4. **Director routes the task:** preserve the owner's words, attach the evidence, acknowledge ownership, and use `node dev/codex/run.ts resume <topic> "..."` from the recorded launcher once idle. If that checkout/build is gone or the base changed, start a new explicitly based job. The web page never executes shell commands. Agent replies with a new version and evidence; unresolved pins remain until reviewed. Acceptance approves that version's look, not automatic deployment.

**[V/D] Human-AI evidence:** Amershi et al.'s [CHI 2019 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf), especially guidelines 9, 15 and 16, supports easy correction, granular feedback and showing its consequences. It studied general AI interfaces, **not** agent-made game assets. Boogle's inference is to show the output before the agent's explanation, retain Can't tell, and show which revision addressed each note. Measure time-to-decision, missing-context follow-ups and reopened notes; do not invent productivity percentages.

## A separate asset and animation stage

**[V]** `?proto=assets` is an in-world scaffold demonstration, not a browser of assets. Actual sources are [assets/src](../../assets/src), outputs [assets/built](../../assets/built), build/check logic [dev/assets/build.ts](../../dev/assets/build.ts), and runtime [render/assets.ts](../../src/render/assets.ts). There is no `src/assets`. [src/blueprints](../../src/blueprints/blueprint.ts) describes collision/footprints, not a visual catalogue. The build manifest records hashes, triangles, textures and clip names; [assetEntries()](../../src/render/asset-manifest.ts) only sees registrations whose modules have loaded. Importing every feature to populate a viewer would also start unwanted game behavior.

**[V] Reuse the existing isolated [/character/ viewer](../../character/main.ts).** It already has orbit/turntable, ten clip buttons, speed, carry/airborne pose helpers, hats/colours, wireframe, triangle/download readout, crowd and `clip`, `t`, `view` links. It reuses retargeting/life code but duplicates loader, lighting and animation timing; its direct Neutral render is not the production-water pipeline. It lacks a general catalogue, scrub timeline, version review and KTX2 loader setup.

**[D] Extend that entry into the asset stage, without loading an island or room.** Keep one renderer/pipeline per standalone document, refactoring the runtime loader/material/tone seams into reusable code. Generate the catalogue from the build manifest plus side-effect-free descriptors; procedural assets get preview factories and blueprint overlays. Preserve `/character/` links; an `/assets/` alias is optional, not another app. Do not turn blueprint data into a second art source.

Default view: asset search/thumbnails, turntable/orbit, ground grid in metres, bounds and actual Buddy alongside for scale, selected clip and a large play/scrub control. Expand inspection for:

- Every clip, duration, loop, speed, exact time, frame step at a stated sampling FPS; bones, sockets, wireframe and root trajectory. glTF key times need not have one native FPS. Show authored travel versus in-place preview; never infer missing root motion from a moving camera.
- **Raw / As played** animation. [Buddy body](../../src/player/buddy/body.ts), [retargeting](../../src/player/buddy/retarget.ts) and [procedural life](../../src/player/buddy/life.ts) combine separate `buddy` and `hero-clips` files, stride-driven blending, carry and airborne poses. Reuse a preview adapter for those real functions; imported clips alone cannot validate shipped animation. Scrubbing procedural layers requires a resettable local preview clock/state, not just setting an AnimationAction's time.
- Runtime node materials and texture channel/mip views; neutral studio and shipped frozen-sky presets, plus optional sunset/night reference presets clearly marked exploratory. No changes to gameplay time. Compare material on both a swatch and the actual mesh.
- Triangles, vertices, material slots, measured preview draw calls, downloaded bytes, texture dimensions/formats and **estimated** resident bytes including mips and actual KTX2 target format. Renderer texture counts are not VRAM bytes; scene draw calls include floor/shadows. Flag stale output, missing clips/bones and existing sidecar budget breaches. Current defaults are 1 MiB/asset and 12 MiB total download, not GPU budgets.
- Two versions with locked camera/time/light; linked scrub and a wipe or matched stills. Loading both raises memory; on phone compare captures or load one version at a time. Label “asset-only comparison” if old assets are running under today's renderer; full-build comparison is different.

**Agent handoff:** add source+sidecar → `npm run assets -- <name>` → check hashes/budgets → capture the same review poses → submit review record → give the owner one proposed link such as `/character/?review=<id>`. The review parameter is proposed; current `clip`, `t` and `view` links already work in source. Keep the viewer's seek/update/dispose lifecycle explicit: the current asset cache has no eviction API and `play()` owns mixer updates through the game loop. A stage/bootstrap seam is real work, not a drop-in HTML wrapper.

## Several grades of exactly the same view

**[V] Actual path:** [scene.ts](../../src/render/scene.ts) owns one linear-HDR `scenePass`, `RenderPipeline` and `renderFrame()`, with default Neutral. [tone.ts](../../src/render/tone.ts) supplies the water-specific AgX curve and temporal GPU exposure meter. [production water post](../../src/render/water/post.ts) receives the underwater HDR composite, applies metered AgX and sRGB itself, and disables `outputColorTransform`. [proto/tone.ts](../../src/proto/tone.ts) handles water-demo, place and look routes differently; its ordinary branch wraps the current output. It is not a safe generic override atop production-water display output. [Look lab](../../src/debug/look-lab.ts) changes materials/lights too; [look-post](../../src/debug/look-post.ts) builds its own scene pass and applies grade after display conversion. Its presets are not interchangeable LUTs.

| Method                            | Feasibility, cost and fidelity [D]                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Live wipe / 2×2 grade grid**    | **Yes, with an output-stage adapter.** Resolve the active path's final pre-tone HDR into one sampleable texture, share one exposure history, remap tile UVs to the whole image, and select that tile's grade before one output conversion. A wipe uses unchanged UVs. Do not repeat scene geometry, water simulation or exposure meters per tile. If the current HDR result is a composed graph, materializing it can require one extra HDR target/pass. A fixed-size grid need not quadruple pixel count, but adds sampling/ALU/branch cost; a naive `select` graph may evaluate every curve. Four full-resolution tiles cost four times the output pixels. Same transforms can preserve colour accuracy; downsampled tiles are not pixel-identical full-size views. Screen-space vignette/dither must use source-image coordinates. |
| **Captured HDR regraded offline** | **Yes for one frozen frame; not from a PNG.** Copy final pre-tone HDR and store exposure/history result, colour space, dimensions, pipeline version and remaining effects. RGBA16F storage is `width × height × 8` bytes before encoding; GPU readback/export and retained attachments are new work. Reusing the exact TSL transform on the saved float texture can closely match that frame; generic Resolve/CPU/LUT processing is not guaranteed pixel-identical. It cannot recompute reflections, lighting, motion or adaptation from one image. An isolated capture is useful for cheap mobile review; portable HDR export is a later feature.                                                                                                                                                                                    |
| **Key/button A/B**                | **Yes; smallest first proof.** Reuse the same output adapter and shared/frozen exposure, swap presets without reload, prewarm curve variants and preserve current camera. Little steady-state overhead, though shader changes may hitch unless prepared. Exact shipped baseline is possible with the identical active path. Animated waves still differ between consecutive frames; freeze the captured texture for exact A/B, never the shared simulation. Touch gets the same A/B button.                                                                                                                                                                                                                                                                                                                                           |

**Recommendation:** implement A/B first to prove the adapter, then a two-to-four-grade live board in the same feature; default phone view to A/B with captured thumbnails. Use one source frame/exposure for grade-only decisions, then verify the chosen grade moving in the real scene. Retain the genuine unflagged baseline: [tone-comparison.md](tone-comparison.md) explicitly says `tone=neutral` uses metering and is not identical to unflagged Neutral. Compare Buddy, timber/train, bright sea and underwater shots; assess shadow readability and clipped highlights as well as attractiveness.

**Choosing the default:** save the exact preset and approval against a build in the review record. An agent promotes those values into a shared production transform/config consumed by both viewer and active post owner, captures the affected shots and follows normal shipping. A browser preference is only a preview. Preserve the [current frozen demo-sky/AgX decision](../decisions.md#look); this research does not approve replacing it. LUT import waits until input/output colour space and transform order are explicit. No measured GPU cost or pixel-equivalence proof exists yet.

## Persistent Dev and an unobstructed camera

**[V]** The readable sibling [Dev-menu plan](../../../../boogle-codex/dev-menu/docs/plans/dev-menu.md) puts Water **inside the pause dialog** so the top layer cannot hide it, and camera lifetime ends on menu close. Its gate is exactly `?dev=1`. That solves mounting but the pause screen blocks the scene the owner wants to inspect. These recommendations intentionally revise that shell/lifetime; retain its disposable-fixture restrictions.

**[D]** Opening `?dev=1` should remember an origin-local preference independent of room/build ID. Explicit `dev=0` and a visible **Turn Dev off** win over storage, clear only Dev preferences, release camera/input and dispose tools (reload when a legacy instrument cannot detach). A tiny bootstrap reads the preference before lazy imports. On deploy, keep enablement but invalidate unsupported settings; show build ID and missing presets. This survives reloads, deploys and rooms on the **same browser/origin**, not another device, private storage or a new subdomain. Enable once per device. Persist dock/bookmarks, not a live free-camera/input grab or a disposable-run authority marker.

Use an always-visible **DEV · Free cam · Report · Off** strip. Dock Water/grade controls beside the canvas, with collapse and left/right/bottom positions; no modal backdrop. On phone/iPad use a short collapsible bottom sheet with safe-area spacing, 44 px controls and the camera/return buttons outside it. Keep a useful scene viewport above the sheet; no hover or keyboard-only operation.

Free cam is a global **Dev-session** toggle, independent of the selected tool and panel visibility. While active, it owns camera input, suppresses avatar movement/interaction, preserves camera/FOV and provides Return. Pointer drag/orbit plus touch movement/up/down controls work while sliders remain usable; typing consumes keys. Blur clears held input; leaving/reloading restores normal camera. Camera-only movement never teleports the body or stops the server. Normal share links strip Dev/debug flags; preferences are never synchronized to friends. Deliberate review links can opt a reviewer in, but opt-in is not owner authentication or shared-cheat authority.

**Next three deliveries, in order:** **(1)** one review card for an existing before/after, acknowledged pinned note, director retrieval and revised-version reply; **(2)** extend `/character/` into the isolated asset stage, proving scaffold `drop` and Buddy raw/as-played motion with one review link; **(3)** the persistent dock/free camera and grade comparison, A/B before grid. Delivery 3 combines ranks 3–4; it is not a claim they are one small patch. Agent acceptance evidence must demonstrate each complete loop before asking for the owner's one gut decision.

**Do not build now:** a level editor, general property/scripting console, a ShotGrid clone, automatic agent art approval, whole-world rewind, live co-op time control, another renderer per grade, an independent asset/material catalogue, or a new telemetry warehouse.
