# Development saves and stage jumps

> **Verdict:** Use a guarded replacement of the current room for the owner's stage playtests; retain isolated seeded rooms for repeatable agent checks. Call it **Replace room with stage**, because it can erase later progress. Keep namespace wipes for breaking development changes; do not build migrations now.
> **Top recommendations:** 1. Keep the live-room workflow. 2. Preserve a verified recovery point before replacement. 3. Warn and coordinate before moving everyone. 4. Resolve personal-state reset semantics. 5. Keep generated stage recipes and targeted cheats separate. 6. Prove replacement and restoration together.
> **Status:** open. Recommendations for [room-fast-forward](../plans/room-fast-forward.md), not implementation approval.

## What the evidence actually establishes

Public support policies describe player-facing development builds, not necessarily a studio's internal workflow. Survios and Retro City Rampage provide direct internal-tool evidence below; engine docs describe available mechanisms. No source here establishes that every studio uses migrations, private shards or checked-in “golden saves.” The comparison distinguishes those mechanisms rather than treating early access as permission for arbitrary loss ([Survios, GDC 2024](https://gdcvault.com/play/1034834/Future-Realities-Summit-Techniques-for), [Retro City Rampage, GDC 2015 slides](https://ubm-twvideo01.s3.amazonaws.com/o1/vault/gdc2015/presentations/GDC15_AutomatedTestingAndInstantReplays_08.pdf)).

### Saves while the game is still changing

| Game / source date | Published practice and its limit |
| --- | --- |
| **Valheim [P], 2024-03-26** | Iron Gate tells PTB players to copy **worlds and characters** before testing: updated saves may not load in the older branch, and friends/server must use PTB too. New biome generation works properly in unexplored areas; a new world is recommended if the target biome was already explored. This is conditional continuity, not a blanket wipe policy. [Ashlands preparation](https://www.valheimgame.com/support/getting-ready-for-the-ashlands/). |
| **Satisfactory [P], accessed 2026-11-12** | Experimental tests features before main; Coffee Stain says to back up when changing versions and copy saves elsewhere regularly, especially with cloud saves. A separate executable/branch alone is not a separate safe copy of data. [Official support](https://www.satisfactorygame.com/support/). |
| **Factorio [P], 2018-11-23; API accessed 2026-11-12** | Wube maintains map-version conversion and tests save/load equivalence for multiplayer/replays. It also retires direct import of sufficiently old versions, offering intermediate releases to convert them. Mod migrations rename prototypes and repair recipe/research state, recording which migrations ran. This buys continuity at the cost of ordering, dangling references and catalog-change handling. [FFF 270](https://factorio.com/blog/post/fff-270), [migration API](https://lua-api.factorio.com/latest/auxiliary/migrations.html). |
| **Minecraft [P], 2024 snapshot; repository accessed 2026-11-12** | Mojang warns that testing versions can corrupt worlds and recommends backups and/or a different folder. Its published DataFixerUpper library incrementally transforms old data, including Minecraft game data. Migration and disposable testing coexist. [24w05b](https://www.minecraft.net/en-us/article/minecraft-snapshot-24w05b), [Mojang source](https://github.com/Mojang/DataFixerUpper). |
| **Stardew Valley [P], 1.6.9 notes, accessed 2026-11-12** | The developer's changelog documents recovering damaged/missing `SaveGameInfo`, resending missed recipes/mail/achievements and reducing corruption. It also adds hidden cheats where save editing is possible. This is evidence of repair and retained debug access, not evidence of an internal always-compatible policy. [Official changelog](https://www.stardewvalley.net/stardew-valley-1-6-9-changelog/). |
| **No Man's Sky [P], 2026-09-11** | Hello Games asks Experimental users to copy the save directory; on returning to main, resume a **main-branch backup**, since an Experimental save may behave unexpectedly. This preserves a return point rather than promising downgrade compatibility. [Developer's Steam post](https://steamcommunity.com/app/275850/discussions/0/567045234501060708/). |
| **Core Keeper [P], 1.0 FAQ, accessed 2026-11-12** | Existing Early Access/Classic worlds remain playable, but some 1.0 content cannot appear there; the publisher recommends a new world for the full experience. “Loads successfully” and “contains the new campaign” are separate promises. [Publisher FAQ](https://fireshinegames.co.uk/customer_support/core-keeper/). |
| **Palworld [P], server docs accessed 2026-11-12** | Dedicated servers expose `bIsUseBackupSaveData` for world backups, with increased disk load; password-authenticated administrators can save, broadcast, teleport and shut down with a message. These are live-world operator tools, not an assertion that arbitrary progression grants exist. [Configuration](https://docs.palworldgame.com/settings-and-operation/configuration/), [commands](https://docs.palworldgame.com/settings-and-operation/commands/). |
| **Enshrouded [P], support updated 2026-04-23** | Its development-era support article describes dedicated-server `saveDirectory`, ten rolling world copies, index-based rollback and copying all files before changes. Treat that as dated format evidence, not a current 1.0 file-layout guarantee. [Save Game Management](https://enshrouded.zendesk.com/hc/en-us/articles/17764283835677-Save-Game-Management). |
| **Rust [P], official hosting wiki accessed 2026-11-12** | A contrasting wipe model: a forced wipe increases the save protocol suffix so the server creates a new map save instead of loading the old one. The wiki distinguishes map saves from blueprint data and warns against renaming an old save to bypass the break. This is close to Boogle's namespace reset; it does not justify arbitrary mid-session resets. The page is undated and is not evidence of today's exact wipe schedule. [Server files and protocol](https://wiki.facepunch.com/rust/Getting-Started_w-Server). |

**Shared-world consequence [D].** A server world is a shared persistence unit, while character/client data may live elsewhere: Valheim explicitly backs up both, and Enshrouded documents server-world files separately. Copying only one player's browser storage cannot restore a group world. Backup before changing builds or worlds; restore with the server's writers stopped or fenced, not by racing autosave ([Valheim server guide, 2024-04-11](https://www.valheimgame.com/support/a-guide-to-dedicated-servers/); [Enshrouded, 2026-04-23](https://enshrouded.zendesk.com/hc/en-us/articles/17764283835677-Save-Game-Management); Boogle's existing writer fence, [rooms.ts:213](../../server/src/host/rooms.ts#L213), inspected 12 November).

## Ways developers reach later stages

Costs below are qualitative maintenance costs [D]. A command affects the world it targets; a debug menu does not inherently make a copy or protect saves. Unreal's save system requires game-defined persisted fields, so even a “whole snapshot” means **whole serialized state**, not every client preference, transient effect or physics body ([Unreal SaveGame, P, accessed 2026-11-12](https://dev.epicgames.com/documentation/en-us/unreal-engine/saving-and-loading-your-game-in-unreal-engine)).

| Approach | Concrete precedent; cost, failure mode and access boundary |
| --- | --- |
| **Debug menu / console** | Unreal `UCheatManager` groups test actions and is not instantiated in Shipping. Unity's `Debug.isDebugBuild` identifies a Development Build; a runtime console can register game commands, but the developer must implement their effects. Cheap entry surface; authority and save semantics remain game work. These build gates suit separate dev builds; Boogle's deployed owner tool needs server authorization instead. [Epic API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UCheatManager), [Unity flag](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityengine/debug/isdebugbuild), [console author's source](https://github.com/yasirkula/UnityIngameDebugConsole), P, accessed 2026-11-12. |
| **Level/chapter select, curated save library** | Survios describes designer-scripted debug saves at different points, importable as `SaveGameDataAsset` and packaged with the game. This supplies chapter-like starts with authored state, rather than only moving a camera. Maintenance follows save/content changes; packaging does not establish how the menu is gated or whether the artifacts are in Git. [GDC 2024 slides, I](https://media.gdcvault.com/gdc2024/Slides/GDC%2Bslide%2Bpresentations/Silkin_Alexander_Techniques%2Bfor%2BEfficient.pdf), indexed “SAVE SYSTEM” excerpt; full PDF fetch returned 403. |
| **Natural-progression debug snapshots** | For Alien: Rogue Incursion, Survios describes quests saving named snapshots during natural progression, plus console save/load by name for midpoint testing, bug reproduction and passing a moment to another developer/build. Whole-save setup reduces omitted prerequisite state, but stale snapshots still need compatibility. [GDC 2025 slides, I](https://media.gdcvault.com/gdc2025/Slides/Silkin_Alexander_Constructing%2Bthe%2BWorld.pdf), indexed “DEBUG SAVES” excerpt; full fetch 403. |
| **“Golden saves” in source control** | The verified engine mechanism is custom save slots, and Survios's indexed evidence is packaged save assets. This pass did **not** establish widespread studio practice of committing milestone save binaries to a repo. For Boogle, version-controlled recipes plus generated current-build snapshots are the better-supported proposal; call a captured save a build-specific fixture, not perpetually golden. [Unreal SaveGame, P](https://dev.epicgames.com/documentation/en-us/unreal-engine/saving-and-loading-your-game-in-unreal-engine), accessed 2026-11-12; [Boogle seed recipes](../../src/sim/railway-seeds.ts), inspected 12 November; D. |
| **Give-item, unlock-all, set-quest-stage / scripted fast-forward** | Bethesda officially recommends loading a pre-command save after console-induced problems. A stage flag is not proof that prerequisite inventory, scripts and world changes agree [D]. Exact `SetStage` behavior is not verified here: the Creation Kit page was inaccessible. Blizzard's documented PTR quest boost is a primary example of a curated prerequisite-completion bundle. Cheap individual cheats become expensive when combined into arbitrary stage transitions. [Bethesda support, P, accessed 2026-11-12](https://help.bethesda.net/app/answers/detail/a_id/31693/), [WoW PTR, P, 2017](https://worldofwarcraft.blizzard.com/en-us/news/20946577/we-want-you-on-the-patch-73-public-test-realm). |
| **Creative mode, scenarios, editor and time acceleration** | Minecraft documents `/give`, game-mode controls, server-console execution and multiplayer permissions. Wube integrated its editor with normal action handling after duplicated editor logic fell behind; it works in multiplayer, supports pausing and simulation/tick-rate control. `/editor` toggles it; scripting cheats disable achievements for that save. These tools are intentionally player-accessible. Wube also permits directly hosting custom multiplayer scenarios. They can edit the current world; scenario hosting supplies a separate starting situation. Faster time still executes intervening simulation; it does not synthesize prerequisites [D]. [Minecraft commands, P](https://www.minecraft.net/en-us/article/minecraft-commands), [Factorio console, official wiki, P](https://wiki.factorio.com/Console), accessed 2026-11-12; [FFF 252, P, 2018-07-20](https://factorio.com/blog/post/fff-252), [FFF 154, P, 2016](https://factorio.com/blog/post/fff-154). |
| **Bots / recorded replay warp** | Retro City Rampage records inputs with deterministic initialization and checksums; its GDC slides sandbox online/achievement systems and use in-memory saves to protect real player saves, including in shipping builds. The Division's GDC abstract describes mission bots, follow bots for solo testing of multiplayer missions and reproduction assistance. Setup/maintenance is higher than loading a seed; replay correctness depends on the starting state and simulation [D]. [RCR, P, GDC 2015](https://ubm-twvideo01.s3.amazonaws.com/o1/vault/gdc2015/presentations/GDC15_AutomatedTestingAndInstantReplays_08.pdf); [The Division, P abstract only, GDC 2019](https://www.gdcvault.com/play/1026382/Automated-Testing-Using-AI-Controlled). |
| **Server admins / MMO GM commands** | Palworld requires a configured admin password and explicit elevation; `/Save`, `/Broadcast` and timed shutdown operate on the live server. AzerothCore documents command security levels and realm-scoped account elevation; its GM command table includes quest/item/level manipulation. AzerothCore is an open-source MMO server implementation, **not evidence of Blizzard's retail GM implementation**. Powerful live commands need server-side roles and recovery, or belong on a disposable realm [D]. [Pocketpair commands](https://docs.palworldgame.com/settings-and-operation/commands/), [AzerothCore GM docs](https://www.azerothcore.org/wiki/gm-commands), P, accessed 2026-11-12. |

**Isolation versus exclusion [D].** Unreal excludes its standard cheat manager from shipping; Minecraft and Palworld retain powerful commands with permissions. These are different valid models. Hiding Boogle's menu with `?dev=1` is neither model's execution guard; use the server secret. A permission protects **who can change everyone’s world**, not everyone’s progress from an authorized operator ([Epic CheatManager](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UCheatManager), [Minecraft commands](https://www.minecraft.net/en-us/article/minecraft-commands), accessed 2026-11-12; [fast-forward plan, Server and safety](../plans/room-fast-forward.md#design), inspected 12 November).

## Mapping the three designs onto Boogle

**As built, not inferred from an old plan [P].** The legacy world is lockstep, but the current railway progression being replaced is **Server-kind replicated state**. Seeds drive accepted sim actions, load through `railwayCheck`, and save through a real host; production prebuilds them. Current `/jump` refuses saved or loaded targets. Admin restore closes a room and replaces its save; it refuses occupied rooms without `force=1` ([namespace history v14](../../src/world/namespace.ts), [seed builder](../../server/src/seeds/build.ts), [jump.ts:185](../../server/src/jump.ts#L185), [admin.ts:73](../../server/src/admin.ts#L73), inspected 12 November). The [fast-forward plan](../plans/room-fast-forward.md) remains planned; the [jump-in plan](../plans/playtest-jump-in.md) contains historical status mixed with built steps.

| Candidate | Fit, relative cost [D] and other players' risk |
| --- | --- |
| **(a) Seed snapshot replaces live room, server key + backup** | Best immediate fit for the owner: same URL/room and a coherent serialized stage; reuses seed/restore machinery. Medium operational work remains. It replaces inventories, construction, economy and vehicle state for **everyone**, including absent friends; a backup offers rollback, not a merge. Restoring it later also discards progress made after the replacement. “Forward-only” against the last chosen seed does not compare against progress actually played. [Fast-forward plan, Options / Design](../plans/room-fast-forward.md), inspected 12 November. |
| **(b) Private seeded room per stage** | Best repeatability and smallest shared-world blast radius; retains original progress. Low additional work because it exists, but invites, room choice and separate history interrupt the owner's preferred flow. It uses the **same deployed service/build**, not a separate staging deployment. The three-day idle deletion means these rooms cannot serve as recovery archives. A random room name isolates collisions; it is not authenticated membership. [Jump-in plan](../plans/playtest-jump-in.md), [as-built Jump in](../game-design/dev-menu.md#jump-in), inspected 12 November. |
| **(c) Granular live progression cheats** | Potentially preserves unrelated builds and account inventory, but highest initial state-reconciliation cost. Flags, granted stock and laid track must agree with conserved resources, gates, jobs, train state and accepted-action ordering. Existing fresh-world builders cannot simply replay onto a played world. A partial failure can leave an artificial hybrid; additive changes still skip friends' intended goals. [Fast-forward plan, Options (c)](../plans/room-fast-forward.md#options), [seed recipes](../../src/sim/railway-seeds.ts), inspected 12 November. |
| **Recommended hybrid** | Use (a) deliberately for group stage sessions, keep (b) for agents/reproduction and checking a seed before replacement; introduce narrowly bounded (c) only for a demonstrated recurring test. One catalog, one serializer and normal authority; no second campaign simulation or second public environment. This combines the owner's workflow with disposable testing, rather than requiring PTR infrastructure. [Owner calls, 13 November UTC](../agents/owner-calls.md), [seed host path](../../server/src/seeds/build.ts); compare [Wube's integrated editor, 2018](https://factorio.com/blog/post/fff-252), D. |

## Numbered recommendations and missing safeguards

1. **Keep namespace wipes; make room replacement an explicit different operation [D].** Preserve [mixed-builds](../agents/mixed-builds.md): no migrations or compatibility framework during development, no namespace bump mid-session. The owner explicitly permits wipes and deprioritizes old-save guards ([owner-calls](../agents/owner-calls.md), 10 November). Rename the plan's control to **Replace room with stage** and show the lost-state categories before execution; a seed ordering restriction is not preservation of earned progress. Factorio's maintained conversions show the real long-term cost, not a requirement to import it now ([FFF 270, 2018-11-23](https://factorio.com/blog/post/fff-270)). Revisit continuity policy when public playtests begin, as the current contract already says.

2. **Make the recovery point durable before discarding the room [D].** Amend [plan step 1](../plans/room-fast-forward.md#steps) to fully validate the target in a throwaway host first, then stop admission/mutation, persist the latest **verified** checkpoint, pin a recoverable backup and replace under the room's exclusion/fence. The existing `offline` closes **unsaved**, `keep` moves the old file, and only the newest **30 across all rooms** survive ([rooms.ts:213](../../server/src/host/rooms.ts#L213), [admin.ts:15–55](../../server/src/admin.ts#L15), inspected 12 November). Specify failure recovery between backup-move, save-write and metadata-write; single-file atomic rename does not make that sequence atomic ([store.ts](../../server/src/store.ts)). Pin until the operator releases it, export a copy beyond the live volume, and keep a restore command with its build/namespace. Comparable protections: Valheim's pre-test copies and Enshrouded's copy-before-rollback instructions (sources above, 2024 / 2026). This is current-operation integrity, not old-save compatibility work.

3. **Coordinate the people before the mutation [D].** Retain the server-only endpoint, disabled-by-default key, rate limit and typed room name in [Design](../plans/room-fast-forward.md#design). Prefer the dedicated key only; accepting the broader `REPORT_TOKEN` weakens its separation. Add a pre-change broadcast/countdown and an explicit occupied-room override; preserve the existing restore's refusal-by-default rather than moving others silently ([admin.ts:73](../../server/src/admin.ts#L73), inspected 12 November). For a two-to-four-person scheduled test, agree once that this session may replace the shared world; do not require a new consent system. Announce effects on absent players too. Palworld provides broadcast and timed shutdown messaging; its admin password is separate from the join password ([commands](https://docs.palworldgame.com/settings-and-operation/commands/), [configuration](https://docs.palworldgame.com/settings-and-operation/configuration/), accessed 2026-11-12). The plan's after-rejoin toast alone is not advance notice.

4. **Resolve `born` and personal state before promising “wardrobe finds stay” [D].** That sentence in [Options](../plans/room-fast-forward.md#options) is not established by keeping the room name. Current [store.ts](../../server/src/store.ts) stamps a birth id; moving its old file and forgetting it can create a new one. [room-reset.ts](../../src/features/room-reset.ts) reloads on changed `born`; [world-reset.ts:127](../../src/player/world-reset.ts#L127) clears room wardrobe/finds/pose/seen state and The Boogler's memory, with claim pruning in [boot/world-reset.ts](../../src/boot/world-reset.ts). Inspected 12 November: this is a concrete conflict with the plan's proposed preservation. Choose and document whether advance preserves that identity and personal claims, and how restore treats them. A server backup alone cannot undo browser deletions. Compare Valheim's explicit world **and character** backup scope ([2024-03-26](https://www.valheimgame.com/support/getting-ready-for-the-ashlands/)).

5. **Keep recipes reproducible; keep cheats narrow [D].** Retain `buildSeedWorld`, [buildSeedDoc](../../server/src/seeds/build.ts), `--rail-seed` and [jump rooms](../plans/room-fast-forward.md#design) for deterministic setup on the deployed build. Record stage, build, namespace and resulting snapshot identity in reports; do not promise saves survive a breaking namespace change. Commit recipes, regenerate artifacts, and reserve full bot runs for reaching/validating the segment's behavior. If repeated live edits later justify a “complete this job” command, use bounded server-authorized accepted actions, explicit preconditions and a recorded result, not field pokes or an unlock-all bundle. Wube's duplicate editor maintenance and Bethesda's pre-cheat-save recovery advice are the relevant cautions ([FFF 252, 2018](https://factorio.com/blog/post/fff-252); [Bethesda support, accessed 2026-11-12](https://help.bethesda.net/app/answers/detail/a_id/31693/)). No live time multiplier or replay transplant follows from a harness warp.

6. **Prove restore as part of the same implementation checkpoint [D].** Extend the [plan's checkpoint](../plans/room-fast-forward.md#steps): two peers on a played room, higher old tick → lower seed tick, reconnect and state agreement; returning absent player; queued/in-flight edits; duplicate/concurrent advance; invalid target and injected failure after backup; then operator restore with the intended `born`/personal-state outcome. Preserve evidence of pre-change, seed and restored checkpoint identity. These are focused save/sync proofs, not a demand for a new compatibility suite or full staging service ([room-safety](../agents/room-safety.md), [tests](../agents/tests.md), inspected 12 November). Factorio's save/load equivalence requirement and RCR's checksummed, sandboxed replays support this acceptance target ([FFF 270, 2018](https://factorio.com/blog/post/fff-270); [GDC 2015 slides](https://ubm-twvideo01.s3.amazonaws.com/o1/vault/gdc2015/presentations/GDC15_AutomatedTestingAndInstantReplays_08.pdf)).

**Limits / disposition.** Prerequisite-first within the owner's live-room scope: amend the plan's recovery and personal-state contract before implementation.
