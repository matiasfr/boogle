# Unreal alignment: keep the browser loop, preserve portable work

_3 November 2026. Live release/roadmap research and Boogle source inspection at `0e4376b1`. Recommendation, not migration approval. Primary passages and photographed slides checked; no Unreal installation, port, timing comparison or device test. House format: [engine architecture](engine-architecture.md), [places as modules](places-as-modules.md)._

## Result

**Stay on TypeScript/three.js for now; align contracts and source assets where that already helps Boogle.** Unreal's agent story is now credible: Epic ships experimental MCP in 5.8 and is explicitly designing UE6 around agents. But moving would replace most runtime integration and the verification/delivery pipeline while Boogle is still proving its loop. This serves **Small and readable**, **Designed for drop-in, drop-out**, and **Clear authority** in [DESIGN](../../DESIGN.md).

**Two announcements today matter:** UE 5.9 Preview is promised next week, including **web as a target platform**; Tokyo slides announce removing Actors, Blueprints and the C++ gameplay framework for UE6. Therefore neither “Unreal necessarily loses the browser forever” nor “copy UE5 Actors to prepare for UE6” is sound advice. Web viability and the transition tooling remain unproved. Evidence and qualifications follow.

**Labels:** **P** = primary Epic documentation/announcement; **P-slide** = Epic slide inspected in a secondary outlet's photograph; **S** = secondary reporting; **L** = inspected local code/docs; **I** = inference/recommendation. Undated living docs below were accessed **2026-11-03**, generally displaying UE 5.8. A feature inside a shipped engine can still be Experimental or Beta. No rumour is used as implementation authority.

## Agents: much better support, still a different working loop

This is the deciding facet because agents write nearly all Boogle's code.

| Capability | Unreal evidence | Consequence for Boogle [I] |
| --- | --- | --- |
| Assistant versus agent | 5.7's assistant answers questions/generates C++; 5.8's **Experimental [Unreal MCP](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor)** actually exposes editor operations, Python/C++ toolsets, Slate inspection and tests; Codex client configuration is supported. Calls run serially on the game thread; APIs/coverage are evolving. **P, Nov 3 docs.** | Agents can manipulate levels/materials/assets; “Unreal requires manual clicking” is obsolete. A connected tool is not proof that it completed and saved the intended edit. |
| Text and binary work | C++, Verse, Python and config are text. `.uasset`/`.umap` are binary for normal Git operations, but [Epic's asset diff tools](https://www.unrealengine.com/blog/diffing-unreal-assets?lang=en-US) provide text exports and Blueprint-aware comparison (**P, 2014-03-28**). [One File Per Actor](https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine) reduces shared-file contention (**P, current**). | “Cannot be diffed” is too absolute; ordinary text merging still does not work. Independent asset ownership, semantic readback and complete changelists become necessary. OFPA does not solve two agents editing the same asset. |
| Scripting and builds | The **Experimental [Python Editor Script Plugin](https://dev.epicgames.com/documentation/unreal-engine/scripting-the-unreal-editor-using-python)** automates editor/import tasks and commandlets; it is **not packaged gameplay scripting**. [AutomationTool](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-automation-tool-overview-for-unreal-engine) and [BuildGraph](https://dev.epicgames.com/documentation/en-us/unreal-engine/buildgraph-for-unreal-engine) support unattended build/cook/test pipelines. **P, current.** | Self-merging PRs can continue, but runners need engine/SDK versions, derived-data caches, asset cooking and platform packaging. Text-driven asset generation helps; compiled outputs still need inspection. |
| Seeing and playing | [Gauntlet](https://dev.epicgames.com/documentation/unreal-engine/gauntlet-automation-framework-in-unreal-engine) runs client/server sessions and test controllers; [Screenshot Comparison](https://dev.epicgames.com/documentation/unreal-engine/screenshot-comparison-tool-in-unreal-engine) checks rendered output. **P, current.** | Rebuild `look`/bot checkpoints, structured state inspection and input control on these foundations. Headless/null-render tests cannot validate the water or Buddy; rendered evidence still needs a GPU. |
| Iteration | [Live Coding](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime) patches C++ at runtime with platform/reinstancing limits; it is not universal mobile hot reload. **P, current.** | Boogle's TS/Vite + Node + browser screenshots has fewer stages than compiler/reflection/editor/cook/package. Expect heavier cold builds and asset conflicts; exact slowdown is **unmeasured**, and parameter edits in Unreal can still be immediate. |

Epic's June statement explicitly backs external models and reports success with indexing, crash/CI analysis and tools; its [Tokyo AI slide](https://gamemakers.jp/cms/wp-content/uploads/2026/11/d2896ba049a872e0cf812669db7f64de.jpg) reiterates user control and MCP/Python model choice (**P/P-slide**). This is unusually relevant support, not proof that an almost entirely agent-written multiplayer game migrates cheaply. Epic also announced [Lore](https://www.unrealengine.com/news/state-of-unreal-2026-top-news-from-the-show) version control on June 17; binary scalability does not establish automatic semantic merges. Keep Git and [Boogle's shipping workflow](../agents/shipping.md).

## Delivery, hardware and licence

- **Browser:** Epic's old [HTML5 support removal announcement](https://forums.unrealengine.com/t/unreal-engine-4-23-released/130478) (**P, 2019**) explains the historical gap; no shipped first-party 5.7/5.8 browser-export path was verified. **Today's 5.9 announcement changes the future possibility.** No verified WebGPU/WebGL/WASM details, Safari support matrix, feature parity, download sizes or browser networking constraints were found. Do not assume the promised web target meets Boogle's instant-link requirement.
- **Pixel Streaming exists today:** the Unreal application runs remotely and sends video/audio plus input over WebRTC ([Epic docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/pixel-streaming-in-unreal-engine), **P**). It preserves a clickable browser entry, but adds GPU hosting, session provisioning, encoding latency and continuous bandwidth. Independent player cameras require separately rendered views; it is not static CDN delivery. **I:** unattractive as Boogle's default for friends casually joining.
- **Mac/iPad/iPhone:** native support exists. Current [Mac requirements](https://dev.epicgames.com/documentation/en-us/unreal-engine/macos-development-requirements-for-unreal-engine) list software Lumen on M1+, Nanite/VSM on M2+ Beta, hardware Lumen/MegaLights on M2+ Experimental: **do not assume Nanite on our M1 Max target**. Native [iOS/iPadOS deployment](https://dev.epicgames.com/documentation/unreal-engine/setting-up-an-unreal-engine-project-for-ios) adds signing/install/distribution. Standard [mobile render paths](https://dev.epicgames.com/documentation/unreal-engine/rendering-features-reference) omit Nanite/Lumen. 5.8's iOS SM6 notes conflict on Experimental/A15+ versus Beta/A17 Pro+/iOS26: treat as unresolved, not desktop parity. **P, accessed Nov 3; not tested on a device.**
- **Size:** native migration adds engine runtime, cooked assets/shaders and platform packages; download/patch size becomes a first-class cost. No defensible Boogle MB/GB estimate or 5.9 web-size benchmark exists here. Measure compressed first-play bytes, installed size and patch bytes separately; an editor installation size is not a shipped-game size. **I**, compared with [Boogle's loading plan](../plans/loading.md).
- **Licensing, checked Nov 3:** ordinary game distribution uses royalties, generally **5% of qualifying lifetime gross product revenue above $1 million**, with exclusions; eligible Launch Everywhere releases reduce the rate to **3.5%**, subject to store/parity requirements. Paid non-game seats are a different model, not an automatic per-agent fee. [Epic licensing](https://www.unrealengine.com/license), [EULA/Royalty Addendum](https://www.unrealengine.com/eula/unreal) (**P**). On **2026-10-29**, [Epic removed specified UE/MetaHuman AI-training restrictions](https://www.unrealengine.com/ue-devs-can-now-choose-to-train-ai-models-on-their-projects); existing users opt into the revised EULA. Fab NoAI and separate UEFN terms remain. No binding UE6 royalty schedule found; recheck at a real migration decision.

**Relative size:** a **whole-game platform rewrite**, several major workstreams beyond the already-needed production railway conversion, not a renderer swap. A greybox walk/chop demo would prove little of the saves, water, mobile and agent workflow. No calendar or percentage estimate is defensible without a representative port. Retaining Node may preserve more code but adds two runtimes and a custom bridge; it is an option to price, not today's recommended architecture. **I.**

## Ordered agent rules and revisit gate

1. **Protect the edit→inspect→friend-play loop.** Keep [shipping](../agents/shipping.md), `dev/look` and typed `src/entity/inspect.ts` evidence; reject alignment that slows browser iteration without a present benefit.
2. **Preserve authority boundaries before engine vocabulary.** Follow `src/world/sync.ts` and the [mainline findings](../plans/mainline-architecture.md); never reshape the production world around the temporary railway protocol or anticipated UE6 transactions.
3. **Keep authored intent portable.** Follow [asset-pipeline](../plans/asset-pipeline.md): sources, units, named clips, stable IDs and reproducible exports; optimise browser outputs freely without throwing sources away.
4. **Share parameters, not an imitation engine.** Feed material recipes, post controls and scalability groups into the existing material-pipeline/graphics-settings tracks; preserve `patchNode` and one render output. No competing implementation here.
5. **Use engine terms only when their semantics match.** Actions, components, prefabs and subsystems can explain a boundary; don't rename Boogle's sync kinds, add an ECS, replace Rapier, switch axes or rewrite code into Verse/C++ in anticipation.
6. **Reconsider only after evidence changes the tradeoff.** Watch November's 5.9 Preview/release notes for actual browser export, Safari/iPad support, networking and package limits; watch MCP coverage and deterministic asset readback, UE6 removal/migration details, renderer/mobile parity, stable Verse APIs and final licensing. Then propose one isolated proof: two players chop/carry/build/save/rejoin, with Buddy and representative water, driven and inspected by agents. Compare first-play bytes/time, frame time on M1 Max/mobile, edit-to-verified-build time and concurrent-agent conflicts against Boogle. Proceed only if the owner accepts distribution costs and the workflow wins enough to fund the rewrite.

**No proof is authorised by this research-only brief.** [Current direction](../direction.md) places Boogle in round-4 discovery; this report records the requested future preference only. Existing independent systems/graphics work keeps its own authorisation. UEFN is useful as a later Verse/Scene Graph learning surface, not a substitute for Boogle's independent browser game. No additional engine shortlist changes today's decision.

**Unverified:** 5.9 final date/features/removals; web runtime/API/size/performance; UE6 migration completeness and final terms; direct official X retrieval and a public Tokyo recording; authenticated engine GitHub branches were not inspected. The Tokyo removal slide was inspected, not merely repeated from a headline. Some living Epic platform pages conflict; version-specific release notes and an actual target build must resolve those before adoption.
