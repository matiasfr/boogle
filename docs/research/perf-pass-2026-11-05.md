# Instance-write optimization — 2026-11-05

> **Verdict:** Redundant instance writes removed, no proven frame-time gain.
> **Top recommendations:** none; measurement record for the instance-write change.
> **Status:** reference.

Local branch `codex/perf-pass`; baseline `bf4773d9` (launcher main), implementation `2c11395e`. No checkout of an older build, push or ship. The branch started at the locally recorded `origin/main`; remote freshness was not checked under the network restriction.

**Result: redundant instance writes removed; no proven frame-time or draw-count speedup.** Quiet-machine measurement was unavailable: Spotlight and media indexing were active, and other broker jobs queued throughout. Counts below are observations of actual completed frames, not estimates; timings are contended relative evidence only. Not tested on a device.

## Protocol

- Used the launcher broker and its existing look, shots and Place playthrough runners. Measurement actions extend `dev/look/evals/place-draws.ts`; CPU uses `window.boogle.prof.table(20)` (240-frame ring), memory uses `renderer.info.memory`. Five seconds at each pose precede a two-frame backend draw probe; CPU sampling finishes before draw instrumentation starts.
- All static samples use native clocks, FOV 62, 960×600 capture. Co-op means two connected peers; counts and CPU below are for the primary peer. The other peer remains at entry. Initial warped co-op runs returned zero CPU values and were discarded for timing, then repeated with `--real`.
- Standard hill, shore, court, meadow and overview poses explicitly use `classic=1`. Town/T1/cove and the working layer use current production `classic=0`. `terrain=cove` was included for the static production runs, but source search found no consumer: these are actual cove camera coordinates, not a verified separate terrain variant. Production pose setup teleports the primary player near the target to place its local shadow coverage.
- The working-layer test uses the existing production T1 real-input bot, measuring only while `phase=laying`. Camera remains fixed during measurement. The baseline machine leaves the camera before its final still; the after capture reframes the machine after measurement. Thus working end stills are not matched-pose pixel proof.
- Texture bytes are the renderer's allocation estimate, not measured physical GPU residency. Draw totals include shadow draws. Moving NPCs, birds and particles change frame counts across fresh runs. No inference of savings from small count differences.

## Cost owners and safe change

At baseline solo town (209 draws), the railway root owns **143 draws: 81 main + 62 shadow**. Within it, the recovery-rack GLB owns **52 (26 + 26)**; named `place kit` meshes total **32 (18 + 14)**. These are nested portions of the root, not additive independent totals. An additional 32 draws are world-space terrain-like BufferGeometry under `Scene/Group[21]`; precise subsystem attribution was not established, so they are not assigned to a source owner here.

Baseline solo town CPU ranks: render submission **2.074 ms**, physics **0.601**, railway update **0.552**, fish **0.400**, sea **0.321**. Across production native static samples the same systems dominate. After solo town: **1.921 / 0.613 / 0.565 / 0.411 / 0.307 ms** respectively. This mixed timing movement under contention does not establish a CPU win.

The implemented change preserves geometry, materials, visibility and shadow coverage:

- Station logs, rails and stones rebuild fixed slots only when displayed counts change; first use always populates them. Collider, stock state and visibility updates still run.
- The continuous machine rack retains construction-time instance matrices when only its count changes.
- Contact blobs compare all 16 exact Float32 matrix values before writing; changed positions still update, with no new allocation or tolerance.

These are version increments, **not counted GPU transfers**. The same four zeros were verified at town, T1 and cove in solo and co-op. During solo laying the rack/stock marks also become zero; contact blobs still update (935 marks/300 frames before; 622/301 after), as expected for moving parts and newly laid track. The layer advances from head 190.5003 to 165.5008 and uses 14 logs during the after sample.

The rack GLB is the strongest draw-reduction candidate. Merging its materials/groups, changing caster limits or culling other meshes was not accepted in this pass: those need separate proof of material, shadow and bounds equivalence. This patch removes confirmed redundant work without changing those contracts.

## Visual and gameplay evidence

**Visual question:** does retaining identical buffers preserve stock, rack geometry and contact shadows, while changed transforms continue to move?

Opened all three frozen comparison boards (town, T1, cove), before/after classic overview stills, before/after production cove stills, solo working stills, after co-op overview/cove stills and both replay end stills. Static geometry, rails, stock and visible shadows remain intact. The frozen control forces identical buffer uploads, then retains the same data on the same build: **0 changed pixels out of 576,000 at each of three poses**, with zero repeat drift. This is exact same-state upload equivalence, not an independent cross-commit replay of every animated state. Cross-commit scene captures contain actor/time differences; no blanket pixel-equivalence claim is made.

Opened six consecutive video frames in two three-frame groups (6.3 s and 7.5 s) from the after working capture. The stocked layer advances along the track with its rail rack and contact shadow attached, then leaves the frame. Curves contain 382 samples / 6.3425 s, intervals 4.8–29.7 ms excluding the initial zero; camera reframe creates a deliberate discontinuity. Real-time feel and smoothness remain unverified.

Baseline full Place playthrough passed. After change, required `at-cove → t1-done` checkpoint replay passed; all expected segment beats completed and no graphics errors were reported. Both working co-op attempts failed before measurement with **“Production T1 needed recovery; no relocation is permitted”** (baseline warped; after native). No failure was bypassed or gameplay changed. The initial checkpoint-list request also failed because this job had no saves yet; the full baseline playthrough supplied them.

`npx prettier --write` was run on changed files. `npm run check` passed after the source change (lint, types, unit/registry/level/asset checks and build); the final `npm run check` also passed, with its log in the evidence bundle. No owner playtest or physical-device validation.
