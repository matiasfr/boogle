# Low-poly post looks: clearer toys, intact water

> **Verdict:** Compare shade, atmospheric depth and soft edges; owner kept Current.
> **Top recommendations:** 1. Keep Current Neutral as the reference and add effects as independent Dev Looks layers. 2. Lead with gentle shade colour, output dither and coherent aerial perspective. 3. Make tinted, distance-faded depth ink the first structural challenger.
> **Status:** superseded by [post-look-round2](post-look-round2.md); see [Look](../decisions.md#look).

_4 November 2026. Live-source research and source audit at `2313fddc`, three.js r187. Screen-space polish for Boogle's low-poly world, with no per-asset painting, retexturing or second material library. Research only: no game code, generated images, captures or new GPU measurements. Not tested on a device._

**Compare restrained coloured shade, atmospheric separation and soft tinted depth edges first. Keep the current water and Neutral control.** Low-poly art benefits when effects explain overlap, contact and distance; it suffers when they outline every triangle, bury colour in AO, or turn water detail into noise. Eight bounded candidates below include exact starting parameters and TSL-oriented recipes. None is an approved default.

Evidence labels: **[L]** inspected local source; **[P]** primary developer testimony, papers, engine documentation or implementation; **[R]** an investigator's own reconstruction, not the shipped renderer; **[I]** inference/proposal. Conference abstracts establish only what they say; linked videos were not watched. All costs and recipes below are engineering estimates unless explicitly described as historical observations.

## Water and coverage are the integration gate

### Which depth belongs to which picture [L/I]

Current order is effectively:

1. Opaque world/sky into the linear-HDR scene target; opaque marine snow can also write depth.
2. Just before the ocean draws, copy viewport colour and depth for refraction. These copies are private to `surface.ts` and are **not** generic post inputs today.
3. Ocean (`transparent:true`, custom premultiplied blending, `renderOrder=-1`, default depth-write on), then other transparent scene draws. In the normal above-water branch its output alpha is 1 because refraction/transmission have already been composed into its RGB.
4. Resolve scene colour/depth; underwater/lens expression uses them, including a 64×36 near-plane water-boundary field and the signed camera depth. That field is **not a full-resolution ocean-surface mask**.
5. Optional bloom, shared exposure, Neutral/AgX, display-linear finishing, sRGB encode. DOM HUD is outside; scene labels and sprites are already inside.

Consequences: final depth usually stops at the visible sea, so it cannot find contact between underwater stones above water. Pre-water depth sees the bed, but outlining it after refraction places ink at the wrong UV and ignores absorption. Underwater distortion changes sample coordinates, so an edge composed after that distortion swims independently unless it uses the identical warp. The existing MSAA shoreline colour repair (`surface.ts`, final `sceneDepth - waterDepth` blend) must remain intact.

### Proposed shared mask, only for candidates that need it [I]

Depth effects require a **visible eligible-surface coverage** signal, not guessed water hue, `worldY < 0`, or “all transparent objects are absent.” The bounded next-job experiment is one optional `RGBA8` MRT alongside the existing scene, with R = eligible opaque coverage, G = visible water coverage and B = protected sprite/overlay coverage. Clear to zero; normal opaque surfaces write R=1; ocean writes G using its actual fragment coverage and clears R where it covers; all sprites, foam particles, world labels and other translucent overlays attenuate R and write B by their coverage. Depth-writing marine snow also belongs to B. Sky remains zero. This is a shared rendering-class policy; no object-by-object authoring or second asset material set. Surface foam is part of water's G, not its own object ID.

A builder must verify the r187 per-attachment writes/blending, alpha-test/alpha-to-coverage, ocean's custom premultiplied blend, built-in SpriteMaterial conversion, and skinned/instanced paths. Do not assume adding `scenePass.setMRT(...)` correctly handles every custom output. Express classifications through shared context/MRT node slots while preserving existing colour/position nodes; do not clone every asset into an “ink material.” If that cannot be made correct without a parallel material library, omit the masked candidates from the first board and report why.

At 1440×900, one RGBA8 target plus its stored four samples is approximately **24.7 MiB** before allocation padding; RGBA16F normals would add approximately **49.4 MiB** more. These are format-size calculations, not measured device allocations. A coverage mask can resolve fractionally; **categorical object IDs cannot be averaged safely**. For ID edges, nearest single-sample IDs or explicit per-sample resolution is a separate cost/aliasing decision. Equal material colour is not identity; merged or instanced geometry complicates automatic object IDs.

For the first masked recipes, require R>.98 across the sampling footprint, fade out effects within .5 m of camera submersion, and erode away the G boundary by 2 output pixels. This deliberately leaves the shoreline and all underwater optics alone. It may create a narrow untreated strip: inspect it, do not silently hide it. Reuse the existing signed camera-depth owner; no CPU readback or duplicate wave simulation. Do not reuse the coarse meniscus field as a surface-ID texture.

An alternative with physically better composition is an **opaque-stage** effect before water's colour copy, letting the water refract/absorb the result and letting later sprites cover it. That needs an explicit opaque/post/water ordering seam and correct stored MSAA attachments; it is not available merely by rearranging `pipeline.outputNode`. Keep it a later architecture option, not an invisible prerequisite for a quick look.

## Effect trade-offs

Cost classes: **A** fused ALU/one lookup in an existing draw; **B** several neighbouring samples or one small auxiliary target; **C** multi-pass neighbourhood work or extra scene draws; **D** large kernels, temporal/history infrastructure or extra lighting buffers. Classes are relative; full-resolution B plus stored MRT can cost more than a small C. No millisecond claim is attached.

| **Palette limiting / LUT**                                   | Coherent hue families; quantization gives a graphic print look. ### Outlines that survive a moving low-poly world [I]

Use a **tinted dark line**, not black: start with display-linear `mix(surfaceColour * .45, linear('#465968'), .35)`, 45% coverage. A 1-output-pixel inner silhouette protects the sky side and avoids expanding into water. Fade opacity from 30 to 100 m; optionally tint toward the same sky fog. Keep width in **output pixels**, while depth texels follow scene resolution; never let adaptive resolution silently double apparent line width. Test fixed scales 1 and .6. Features narrower than two scene pixels should lose line opacity rather than become black wires.

Use linear depth and a local plane/slope rejection, not an absolute nonlinear depth delta. A first diagnostic can use the second difference `abs(zLeft + zRight - 2*zCentre)` plus its vertical counterpart; a later version should reject expected plane changes using reconstructed positions/normals. For normal edges, compare world/view-space directions consistently, reject mixed-coverage samples, and keep the normal threshold broad (.35–.6 in `1-dot(n0,n1)`). A 90° normal break can still be an intentional facet; there is no universal numerical fix. Do not blur the asset's normals just to satisfy an edge filter.

Keep MSAA 4×. Smoothstep/derivative feathering reduces hard threshold pops but **does not reconstruct missing subpixel geometry**. Depth/ID sampling is point-based; interpolating depth across silhouettes invents surfaces. Wide kernels thicken distant lines and eat fronds. Post FXAA/SMAA can smooth ink but also soften the sea, so add neither automatically. TRAA requires motion/history, transparency handling and disocclusion tests; it is outside this quick comparison.

## Ranked shortlist: eight build recipes [I]

All settings are **starting hypotheses, not recovered game settings or measured optima**. Default control: current Neutral, trim 1, frozen procedural sky `.24`, 4× MSAA, existing material/water settings, bloom off, exposure locked after settling. A separate secondary board may apply the winning effect to AgX with a deliberate grey/exposure match; do not silently use Clean toys' +.375 EV trim.

Common notation for the sketches: `C` is display-linear RGB after the selected tone mapper; `S` is encoded sRGB; `H` is linear HDR before tone mapping. `D` is resolved depth; `uv()` uses the output UV convention; `outputSize` and `sceneSize` are distinct uniforms from the current resolution owner. `P` is reconstructed world position. `eligible(uv)` is the proposed mask R, `water(uv)` its G. `dry` is `smoothstep(.1, .5, -cameraWaterDepth)`, with signed camera depth positive underwater from the existing water owner. The conservative spatial gate is `dry * product(step(.98, eligible(tap))) * (1 - max(water(tap)))` over the kernel footprint, expanded by 2 output pixels at water edges. Sky is ineligible. These helpers are **new integration work**, not existing APIs.

TSL fragments below illustrate node expressions, not compiled modules. Import node operators from `three/tsl`, keep texture sampling/derivatives in uniform control flow, use explicit `.level(0)` for diagnostic point samples, and use increasing `smoothstep` edges. Convert hex colours through `new THREE.Color(...)` and `color(...)`, never raw hex-like `vec3` values. Wire through the current output owner, retaining a real effect-off graph that skips target updates. Prewarm structural variants; ordinary strength/colour/fade edits use uniforms. Exclude DOM HUD by keeping it outside the canvas, as today.

### 1. Coloured shade, neutral highlights — A, no new buffers

Add a luminance-preserving cool bias only to darker midtones; leave near-black, bright paint and white foam alone. Strength **.10**, window **.02–.08 rising, .18–.40 falling**; tint multiplier **(.92,.99,1.08)** in linear space. This is a global split-tone grade, explicitly not actual shadow detection. Apply before existing sRGB encoding in `post.ts`/`prepareLooks`.

```ts
const y = dot(C, vec3(0.2126, 0.7152, 0.0722));
const w = smoothstep(0.02, 0.08, y)
  .mul(smoothstep(0.18, 0.4, y).oneMinus())
  .mul(0.1);
const t = C.mul(vec3(0.92, 0.99, 1.08));
const sameY = t.mul(y.div(max(dot(t, vec3(0.2126, 0.7152, 0.0722)), 1e-5)));
const shadeLook = mix(C, sameY, w);
```

Sweep strength **0/.10/.20**, with .20 only a diagnostic. Reject if cyan shallows/green foliage turn muddy, name-label whites change, or dark Buddy paint becomes indistinguishable. No water/depth classification needed; underwater remains continuously graded.

### 2. Clean gradients — A, no new pass

Output dither **±.5/255**, static, same scalar on RGB to avoid coloured speckles, after sRGB encoding and before 8-bit output. Use a procedural hash first; no generated texture needed. No visible grain in the lead look.

```ts
const p = floor(uv().mul(outputSize));
const n = fract(fract(dot(p, vec2(0.06711056, 0.00583715))).mul(52.9829189));
const dithered = clamp(S.add(n.sub(0.5).div(255)), 0, 1);
```

This is a deterministic screen-space distribution, not a claim of blue noise. Compare **0/.5/1.0 code-value amplitude** (the sketch is .5). Keep the same pattern across A/B. Sky ramps, dark underwater gradients and slow pans are the test; do not animate the noise to disguise banding without a separate motion review.

### 3. Air between islands — A in shared fog, no post depth required

Retain existing distance fog colour and factor. Add a low capped height-density contribution, globally shared by opaque fog and ocean surface fog: sea-level density **.0015 m⁻¹**, height falloff **.035 m⁻¹**, start **40 m**, maximum extra fog **.18**, fade extra contribution to zero as base fog reaches 1. Use the same sky radiance; **not** a flat cyan overlay. Keep current cave transition and disable additional air density underwater.

For a homogeneous ray through exponential height density, let `L=length(P-cameraPosition)`, `q=.035*(P.y-cameraPosition.y)`, `rho0=.0015*exp(clamp(-.035*cameraPosition.y,-8,8))`. Integrate along the entire ray, with a start-distance weight rather than abruptly shifting the height origin:

```ts
const safeQ = select(abs(q).lessThan(1e-3), float(1e-3), q);
const integral = select(abs(q).lessThan(1e-3), q.mul(-0.5).add(1), exp(q.negate()).oneMinus().div(safeQ));
const tau = rho0
  .mul(L)
  .mul(integral)
  .mul(smoothstep(40, 80, L));
const extra = min(exp(tau.negate()).oneMinus(), 0.18).mul(dry);
const totalFog = baseFog.add(baseFog.oneMinus().mul(extra));
const fogged = mix(unfoggedHDR, existingDirectionalSky, totalFog);
```

Clamp `q` to [-8,8] for this bounded outdoor trial; all distances/heights use metres and the same sea-level datum. Use the ocean's surface position, not refracted bed depth. Do this **instead of** the current fog mix at each owner. A post-only implementation would need depth and the mask, mishandle sprites, and double existing fog; it is not the recommended shortcut. Soft particles currently opt out of fog, so record that mismatch before deciding whether one shared pool patch is worthwhile.

### 4. Coloured silhouette ink — B plus optional coverage MRT

Depth-only, inner edge, **1 output px**, opacity **.45**, colour `mix(C*.45, linear('#465968'), .35)`. Fade **30–100 m**; normal weight **0**. Five depth samples at centre/left/right/up/down, clamped UVs; positive linear view distance `z=-perspectiveDepthToViewZ(D,near,far)`. Samples whose raw depth is background still provide silhouette contrast but never become eligible centres. Start with relative discontinuity **.015–.04** and use a second-difference slope gate:

```ts
const rel = max(max(zL, zR), max(zU, zD)).sub(z).div(max(z, 0.5));
const bend = max(abs(zL.add(zR).sub(z.mul(2))), abs(zU.add(zD).sub(z.mul(2)))).div(max(z, 0.5));
const e = smoothstep(0.015, 0.04, rel).mul(smoothstep(0.006, 0.02, bend));
const fade = smoothstep(30, 100, z).oneMinus();
const ink = mix(C.mul(0.45), color(new THREE.Color('#465968')), 0.35);
const outlined = mix(C, ink, e.mul(fade).mul(0.45).mul(outlineGate));
```

For this outline only, `outlineGate` requires the **centre** eligible but permits background neighbours for silhouettes; reject neighbours containing **water or protected overlays**, not sky. The mask therefore needs a protected-overlay flag (B) as well as R/G, or an equivalent conservative coverage test. Reject centre/near-object mixed coverage, and dilate the water/protected exclusion by 2 output pixels. This distinction prevents the all-neighbours-eligible common gate from erasing every useful silhouette. Sampling offset is `vec2(1,0)/outputSize` etc.; depth lookup snaps to the centre of its scene texel, avoiding interpolation across depths. Low scene scales may collapse offsets: clamp support to at least one scene texel and reduce opacity by `min(sceneSize.y/outputSize.y,1)` rather than pretending width stayed exact.

This is a cheap diagnostic, not a perfect plane classifier. A foreground rail with only one scene pixel of coverage may still flicker; fade ink on thin coverage rather than increasing radius. Optional second column adds a normal term at **.45–.65 `1-dot`**, opacity **.10**, only within **15 m**, using already available/reconstructed normals. Do not allocate a full normal attachment just for that column. If facets dominate, drop it. Place the result before sRGB, with all water/underwater and protected overlays bypassed.

### 5. Small luminous accents — C, reuse current bloom

No new bloom implementation. Compare existing chain **off / strength .025 / .05**, threshold **1.5 unexposed HDR**, existing soft knee `threshold*.5`, existing six-down/five-up structure. Main candidate is **.025**. Keep gain locked and log it, so the threshold's scene-radiance meaning is reproducible.

```ts
// Existing owner already builds these nodes; change its bindings, do not instantiate a second chain.
const exposed = bloom.hdr.add(bloom.glow.mul(0.025)).mul(sharedGain);
const C = toneMapping(NeutralToneMapping, 1, vec4(exposed, 1)).rgb;
```

If the next job deliberately changes to an exposed-HDR threshold, it must do so for every comparison and avoid multiplying gain twice; that is a separate convention change, not part of this recipe. Inspect sky-dominated glare, white foam, label whites and underwater shafts. A threshold does not distinguish emissive stars from bright sand. This candidate mainly measures a useful combination with the new cheap layers, rather than rediscovering bloom.

### 6. Small, tinted contacts — C, conditional revisit

Only build if the unmodified town/Buddy comparison shows a contact deficit. Start radius **.35 m**, intensity **1**, final darkening cap **.12**, fade **15–35 m**, half resolution, no temporal accumulation. Use the coverage mask to reject water/protected samples and receivers; run the candidate only in dry views. Standard-node shared AO context before lighting is more correct but requires a prepass; this recipe is explicitly a bounded post approximation.

```ts
import { ao } from 'three/addons/tsl/display/GTAONode.js';
import { denoise } from 'three/addons/tsl/display/DenoiseNode.js';
const g = ao(D, null, camera); // installed r187 reconstructs normals when null
g.resolutionScale = 0.5;
g.radius.value = 0.35;
g.thickness.value = 0.5;
g.samples.value = 8; // structural compile: prewarm, not a continuously swept slider
g.useTemporalFiltering = false;
const a = denoise(g.getTextureNode(), D, null, camera).r;
const occ = clamp(a.oneMinus(), 0, 1)
  .mul(0.12)
  .mul(smoothstep(15, 35, z).oneMinus())
  .mul(aoGate);
const contacted = C.mul(vec3(1).sub(vec3(1, 0.92, 0.8).mul(occ)));
```

The blue-biased remaining light is an artistic tint, not coloured radiometric AO. `aoGate` must reject the **whole projected .35 m footprint** near water/overlays; merely setting water's final `occ=0` leaves dark halos on neighbouring land. For the first comparison that can conservatively bypass shoreline contacts. To support contacts right beside water requires masked gather/depth separation, beyond wiring stock nodes. Likewise do not let denoise gather across protected labels; either conservatively bypass their footprint or extend the filter.

Compare with installed `ssao(D, normalTexture, camera)`: `resolutionScale=.5`, `radius=.35`, `intensity=1`, `bias=.05`, `samples=8`, `blurEnabled=true`, `blurSharpness=8`. It needs a sampled normal texture; reconstruct one with `getNormalFromDepth` into an optional half-resolution target if no existing normal MRT exists. Count that extra draw plus AO and two blur draws. GTAO null-normal mode avoids that target but spends more depth reads. Denoise parameters stay at installed defaults for the first paired trial. Record actual work and do not declare either universally cheaper.

### 7. Soft print bands — A after mask, explicitly not cel shading

Masked dry opaque pixels only. Quantize display-linear luminance into **6 intervals**, blend **.18**, protect values below **.04** and above **.65**, feather step transitions by **.08 of an interval** or `fwidth` if larger. Preserve RGB ratios. This tests whether larger value groups help the low-poly forms without pretending to recover direct lighting.

```ts
const y = dot(C, vec3(0.2126, 0.7152, 0.0722));
const q = y.mul(6),
  base = floor(q),
  f = fract(q);
const aa = max(fwidth(q), 0.08);
const yBand = base.add(smoothstep(float(0.5).sub(aa), float(0.5).add(aa), f)).div(6);
const protect = smoothstep(0.04, 0.1, y).mul(smoothstep(0.65, 0.85, y).oneMinus());
const banded = C.mul(mix(y, yBand, protect.mul(0.18).mul(eligibleCentre).mul(dry)).div(max(y, 1e-5)));
```

Compare **.18/.35**, but .35 is the deliberately stronger boundary. This preserves hue ratios, not exact perceptual hue after clipping; clamp only at final SDR output and check saturated Buddy colours. No full cel-material conversion. For a later **true** ramp, the shared lighting expression would be `albedo * (ambient + lightColour * ramp(NdotL, shadowVisibility)) + specular + emission`; the ramp cannot be correctly recovered from `C/albedo` when albedo is unavailable and reflections/emission are mixed in.

### 8. Small painterly grouping — C/D, desktop experiment last

Use the simple four-quadrant version first, **radius 2 scene pixels**, 25 unique colour taps, sector means/variances from four overlapping 3×3 quadrants, blend **.15**, fade **15–35 m**, dry opaque mask. Process a materialized **tone-mapped display-linear** colour target before encoding; no HDR variance thresholding driven by sun peaks. Downsampling first changes the apparent brush size, so do not combine it with half resolution in the first proof.

```ts
// TSL Fn with fixed JS-unrolled offsets [-2..2]², each colour sampled once at explicit LOD 0.
// For each quadrant Q: mQ=sum(c)/9; vQ=max(sum(dot(c,c))/9-dot(mQ,mQ),0).
// Start result=m0, best=v0; use select(vQ<best,mQ,result) and min(best,vQ) for Q1..Q3.
const amount = float(0.15)
  .mul(smoothstep(15, 35, z).oneMinus())
  .mul(kernelGate);
const painted = mix(C, minimumVarianceMean, amount);
```

`kernelGate` requires all 25 samples eligible and no water/protected coverage within the additional 2 px guard. That deliberately skips silhouettes and labels rather than smearing them; inspect the transition. Fetch colour/depth/mask outside divergent selection. Cost is at least one colour materialization plus neighbourhood work; do not repeatedly inline tone mapping/underwater evaluation 25 times. The [anisotropic algorithm and reference implementation](https://github.com/jkyprian/polyakf) add structure-tensor/orientation work, improving directional treatment but materially increasing scope. Revisit only if this cheap small-kernel trial has a clear visual benefit and survives motion. No claim that a named shipped game uses it.
