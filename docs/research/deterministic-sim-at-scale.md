# Make desyncs diagnosable before making grids bigger

Boogle's shared sim already follows the pattern that shipped deterministic games converged on. Clients send edits, the host stamps them a few ticks ahead, everyone steps the same integer sim, and hashes plus snapshots catch drift. Its automatic snapshot resync is more forgiving than classic RTS lockstep, where a mismatch simply ended the match. The useful lessons from Factorio, Age of Empires, Supreme Commander, GGPO, Overwatch, Photon Quantum and Teardown are therefore not "switch architectures". They are about three things Boogle lacks today: **telling which system desynced and why**, **hashing and resyncing only what changed**, and **keeping sleeping regions asleep as the grid grows**. Rollback netcode solves a latency problem Boogle doesn't have, at a CPU cost it shouldn't pay; Boogle should borrow GGPO's sync test as a unit test instead. The highest-value next steps are cheap. Send per-subsystem hashes, add a save/load/step equivalence test, and show players a cosmetic preview of their own pending edits. Chunk-level dirty tracking, incremental hashes and partial resync are worth prototyping once the grid or player count actually grows.

## Every shipped lockstep game hashes; the good ones also say where it broke

Desync detection splits into a cheap always-on check and an expensive diagnostic. Factorio's default multiplayer check is a **"heuristic CRC" computed every tick** from a handful of cheap indicators: player state, the number of active entities and a production-statistics snapshot. The **full-state CRC, whose cost scales with map size**, is kept as a debugging tool, alongside a mode that saves, loads and verifies the game every tick ([FFF #55](https://factorio.com/blog/post/fff-55)). When a real desync happens, Factorio writes a report containing **"the game state from the server and the client"**, and developers diff the two ([FFF #188](https://factorio.com/blog/post/fff-188)). Age of Empires checksummed the world, objects, pathfinding and targeting separately. Its successor wrapped sync checks in per-system macros that recorded file and line, because "very subtle differences would multiply over time" and the team was otherwise sifting through 50 MB traces ([1500 Archers](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond)). Photon Quantum sends a checksum every **60 frames by default**. On a mismatch it raises an error carrying each client's checksum and collects frame dumps from the other clients for diffing ([Quantum session config](https://doc-api.photonengine.com/en/quantum/current/class_photon_1_1_deterministic_1_1_deterministic_session_config.html), [ChecksumErrorFrameDump](https://doc-api.photonengine.com/en/quantum/current/class_photon_1_1_deterministic_1_1_checksum_error_frame_dump.html)). At the other extreme, Supreme Commander hashed the whole state **once per second** and closed the game on any mismatch. Its developers then binary-searched memory hashes across machines that looped games until one broke ([Forrest Smith](https://www.forrestthewoods.com/blog/synchronous_rts_engines_and_a_tale_of_desyncs/)).

Boogle hashes every **20 ticks (2 s)** and folds every registered state into **one combined uint32** ([src/world/sync.js](../../src/world/sync.js)). On a mismatch the client asks for a full snapshot and silently replaces its state. That recovery is the right player-facing behavior, since nobody gets kicked. It also erases the evidence. Today a desync shows up only as a `hashBad`/`resyncs` counter. Nothing records whether water, terrain or mushrooms drifted, at which tick, or which cell. Several friends and their agents push to `main` concurrently, so a determinism bug can land unnoticed and get papered over by resyncs indefinitely. The gap that matters is observability, not detection frequency.

The causes these teams report line up with Boogle's rules. Supreme Commander's top offenders were **uninitialized variables, floating point and a dangling pointer reused by a new allocation** ([Forrest Smith](https://www.forrestthewoods.com/blog/synchronous_rts_engines_and_a_tale_of_desyncs/)). GGPO's guide adds RNG state not being part of the saved state, wall-clock time used as state and static variables hiding state ([GGPO Developer Guide](https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md)). In JavaScript the equivalents are a module-level variable outside `serialize()`, a `Map` iterated in insertion order that differs between host and joiner, and a float that sneaks into a feedback path.

## Rollback hides twitch latency; Boogle needs a cosmetic preview instead

GGPO predicts missing remote inputs and re-simulates from the divergence point when the real ones arrive. That requires the game to save state, load state and advance a frame without rendering, so every misprediction multiplies sim cost by the rollback depth ([ggpo.net](https://www.ggpo.net/)). The tradeoff makes sense where one frame of delay is visible. GGPO says most intermediate fighting-game players notice more than one frame, while board and puzzle games tolerate **4-5 frames** ([GGPO Developer Guide](https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md)). Overwatch rolls back only the local player's own predicted movement, on **16 ms command frames**. When the server's input buffer runs dry, it tells the client to run slightly faster (15.2 ms frames in the talk's example) until the buffer refills ([GDC Vault](https://gdcvault.com/play/1024001/-Overwatch-Gameplay-Architecture-and); [transcript](https://www.sohu.com/a/148848770_466876)).

Boogle's shared inputs are digs, piles, plantings and sloshes. They are slow, spatial and strategic, like RTS commands. AoE players didn't notice **~250 ms** of command latency and found **250-500 ms** playable ([1500 Archers](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond)). Boogle's 3-tick delay is 300 ms plus transit. Rolling back a 16k-cell water grid to shave that off would buy little and cost real CPU. Factorio offers the better model. It never rolls back the authoritative Game State. It keeps a separate **"Latency State"** that is "not sacred", rebuilt each tick from the real state plus a queue of the local player's own pending actions, so your own clicks look instant ([FFF #302](https://www.factorio.com/blog/post/fff-302)). For Boogle that means a purely cosmetic overlay. A dug hole dents the mesh immediately, a ghost sand puff appears at once, and both are discarded the moment the stamped edit applies. This fits DESIGN.md's rule that cosmetic layers stay separate, and it removes the most noticeable lag without touching the sim.

GGPO's lasting gift to a game like Boogle is the **sync test**. It is a single-player mode that does a one-frame rollback every frame and errors if the replayed frame differs from the first execution ([GGPO Developer Guide](https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md)). Factorio's "save, load and check every tick" mode is the same idea ([FFF #55](https://factorio.com/blog/post/fff-55)). Boogle's water module already claims that `load()` waking every cell is "state-equivalent to an uninterrupted run" ([src/sim/water.js](../../src/sim/water.js)). A sync test turns that claim into a guarantee. Run N ticks straight. In a second run, serialize and load at every tick (or every k-th). Compare hashes. This catches exactly the bugs a snapshot resync hides: state left out of `serialize()`, sleep flags that leak into results, and order-dependent loads.

## Late join is a solved problem at Boogle's size; snapshot plus pending inputs wins

Three late-join patterns appear in practice. Factorio uploads the map in the background, also forwards every input since, and has the joiner replay them as fast as it can. A joiner that falls behind affects nobody else ([FFF #149](https://www.factorio.com/blog/post/fff-149)). Quantum supports pluggable snapshot providers, splits large snapshots across messages, and copies the frame before serializing it on a worker thread ([Quantum API](https://doc-api.photonengine.com/en/quantum/current/class_quantum_1_1_experimental_1_1_quantum_snapshot_provider_demo.html)). Teardown, launched in March 2026, chose to **replay the deterministic command stream**. The command buffer is size-limited, so **join-in-progress is disabled when it fills**, and full-scene saves run 30-50 MB ([Voxagon](https://blog.voxagon.se/2026/03/13/teardown-multiplayer.html)). Classic RTS games skipped join entirely: syncing ~3,000 units was "just too much" ([Forrest Smith](https://www.forrestthewoods.com/blog/synchronous_rts_engines_and_a_tale_of_desyncs/)).

Boogle already does the Factorio pattern. Its snapshot carries `pend`, the edits stamped but not yet applied, so a joiner misses nothing ([src/world/sync.js](../../src/world/sync.js)). Command replay would be wrong for Boogle. The world persists across sessions and grows offline, so there is no bounded log to replay. The one place Boogle diverges from Quantum is serialization. Its snapshots are `JSON.stringify` of sparse integer lists, sent as 7,000-character chunks, with at most 400 chunks. Encoding typed arrays as base64 or run-lengths relative to the base terrain would shrink snapshots several-fold and cut chunk counts. It matters only when a snapshot gets near the chunk cap, so measure first.

The bigger scaling idea is partial resync. Today every mismatch costs a full snapshot. If each state hashed per chunk (for example, 16x16-cell tiles), a client could report which tiles differ and the host could send only those. Factorio and Supreme Commander had no reason to build this, because their desyncs were fatal or rare. Boogle treats resync as routine recovery, so it gains more from it than they would have.

## Integers already beat fixed point; JS adds a few sharp edges

Every engine here that guarantees determinism keeps floats out of the shared state. Quantum's `FP` is **Q48.16 fixed point**, and its float conversions are labelled `_UNSAFE` ([Quantum FP](https://doc-api.photonengine.com/en/quantum/current/struct_photon_1_1_deterministic_1_1_f_p.html)). Teardown rewrote destruction in fixed-point integer math. Transforms and velocities stayed float and went to state sync instead ([Voxagon](https://blog.voxagon.se/2026/03/13/teardown-multiplayer.html)). Gaffer warns that float results can differ across compilers, operating systems, instruction sets and even debug versus release builds ([Gaffer on Games](https://gafferongames.com/post/deterministic_lockstep/)). Boogle's integer centimetres are the simplest form of the same idea. Its split between deterministic grid and owner-synced cannon-es ball is the hybrid Teardown arrived at after years of saying full determinism was unrealistic.

JavaScript adds its own traps. ECMA-262 only *recommends* fdlibm for `Math.sin/cos/tan`, so engines differ ([Mozilla dev-platform](https://groups.google.com/a/mozilla.org/g/dev-platform/c/0dxAO-JsoXI)). One JS physics engine saw `sin/cos` differ between Node and Chrome while `Math.sqrt`, which IEEE 754 specifies exactly, agreed ([bounce #8](https://codeberg.org/perplexdotgg/bounce/issues/8)). Boogle's recent "ban native trig" commit is the correct response. JS also lacks a fast int64, so Quantum's Q48.16 doesn't transfer. If fractional quantities are ever needed (sub-centimetre flow, slopes, growth rates), use Q16.16 or narrower in int32. Multiply with an explicit split, or keep products below 2^53, and finish with `|0` or `Math.imul`. Bitwise ops silently truncate to 32 bits, so values above 2^31 that pass through `|0` wrap without warning.

## Sleep, dirty rectangles, then threads: the order the big sims scaled

Factorio's first rule of performance is that most entities **"go to sleep" when idle and cost nothing**. Next it groups homogeneous work, with solar panels computed per group, and replaces per-item belt updates with segments that shift an offset ([FFF #148](https://factorio.com/blog/post/fff-148)). Noita's falling-sand world tracks a **dirty rectangle per chunk** and only later parallelizes by updating chunks in a **checkerboard** pattern. Developers who copied it report particles **getting stuck at chunk borders** when a dirty rectangle fails to wake its neighbor ([GDC Vault](https://gdcvault.com/play/1025695/contactUs); [BeefSand](https://github.com/BradFitz66/BeefSand)). DESIGN.md already states this order: sleep settled regions before reaching for workers or the GPU. Boogle's water uses a per-cell quiet countdown that wakes neighbors and simulates only the land bounding box ([src/sim/water.js](../../src/sim/water.js), [src/sim/water-region.js](../../src/sim/water-region.js)).

Players and grid size scale different costs. Lockstep bandwidth tracks inputs, not world size: "a million objects" can cost the same as one ([Gaffer on Games](https://gafferongames.com/post/deterministic_lockstep/)). Teardown found that sending voxel data instead of commands "completely choked" the connection ([Voxagon](https://blog.voxagon.se/2026/03/13/teardown-multiplayer.html)). With six players, edit traffic is trivial. The risk is bursts: Factorio's 200-player event hit a megapacket when a catching-up client batched ~400 actions into one tick ([FFF #302](https://www.factorio.com/blog/post/fff-302)). Boogle's per-op `validate` rate limits and `MAX_STEPS = 5` already bound this. Grid size drives sim and hash cost. Boogle's grid is 129x129, about 16,641 cells. A full-scan FNV hash every 2 s costs nothing at that size. At 513x513 (263k cells), or with hashing every tick, it becomes the first cost worth removing. Per-chunk dirty flags then do triple duty: they skip sleeping chunks in the step, refresh only dirty chunk hashes, and enable partial resync.

## Prioritized recommendations for Boogle

| # | Adopt / prototype | Why (precedent) | Sketch | Cost |
|---|---|---|---|---|
| 1 | **Per-subsystem hashes on the wire** | AoE per-system checks, Quantum per-client checksums | `w:hash` carries `{h, parts:{water, terrain, mushrooms, ...}}`. The client logs which keys differ, plus the tick, in `worldStatus()` and `?netdebug=1` before resyncing. | Small; `sync.js` only |
| 2 | **Sync-test unit test** | GGPO synctest, Factorio save/load-every-tick | A `test/*.test.mjs` per state: run N ticks with seeded edits, then rerun with serialize then load (via JSON) at every tick and require identical hash sequences. Shrink grids to keep it under a second. | Small; pure sim |
| 3 | **Cosmetic preview of your own pending edits** | Factorio Latency State | On `submitEdit`, apply a local cosmetic dent or sand puff, keyed by a client-side id, and clear it when the stamped edit applies (`onApplied`) or after a timeout. Never touches sim state. | Small to medium; feature module |
| 4 | **Desync dump (dev only)** | Factorio desync report, Quantum frame dumps | Under `?netdebug=1`, on mismatch keep the client's `serialize()` of the differing parts and the host snapshot it receives, then diff per cell in the console or in `dev/peer-test/`. | Small |
| 5 | **Chunk-level dirty tracking in water** | Noita dirty rects, Factorio sleep | Add a 16x16 tile `awake` bitmap so the step skips whole sleeping tiles. Wake tiles with a one-cell margin across borders, to avoid the Noita border-stuck bug. Measure first (`npm run look` perf). | Medium |
| 6 | **Incremental per-tile hashes** | Zobrist incremental update, Factorio heuristic CRC | Each tile keeps a cached hash, recomputed only when that tile was dirty this tick. The world hash combines tile hashes in fixed order, mixing in the tile index (not plain XOR, which cancels identical tiles). This allows cheaper and more frequent checks. | Medium; after #5 |
| 7 | **Partial resync by tile** | Extends Quantum snapshot provider | On a mismatch, the client sends the tile-hash vector and the host sends only differing tiles plus `pend`. Fall back to a full snapshot if more than 25% differ. Needs `check:full` and a peer-test. | Medium to large |
| 8 | **Binary snapshot encoding** | Quantum multi-message snapshots | Base64 typed arrays, or RLE against base terrain, inside the existing JSON envelope. Do it only when snapshot size approaches `MAX_CHUNKS`. | Small; measure-gated |
| 9 | **Adaptive edit delay** | AoE speed control, Factorio 5 s latency renegotiation | Only if playtests show late-edit resyncs (`stats.lateEdits`) for far-away peers. The host raises `DELAY` while any client's measured lag nears `LEAD`, and decays it slowly. | Small; watch stats first |

Avoid these:

- **Rollback of the shared grid.** CPU cost multiplies by rollback depth, and the inputs are latency-tolerant.
- **Command-log replay for late join.** It is unbounded in a persistent, offline-growing world; Teardown has to disable join when its log fills.
- **Full-state hashing every tick at a larger grid size.** Factorio keeps that for debugging.
- **Float or native trig anywhere that feeds back into shared state**, including "harmless" growth curves.
- **Workers or the GPU before chunk sleep is measured.**
- **Fatal-on-desync, Supreme Commander style.** Keep silent resync for players, but make it loud for developers.

## Conclusion

Supreme Commander and early Factorio were rich in tooling and poor in recovery: desyncs were fatal, so every one had to be found. Boogle has the opposite profile. Recovery is automatic and cheap, so desyncs become invisible, and that is riskier in a repo where many agents push to `main` at once. Its next investment in determinism should go into evidence rather than more recovery machinery. Per-subsystem hashes, a sync test in `npm run check` and a developer-only desync dump would make one bad commit loud within a day.

The scaling path is one data structure, not several systems. A per-tile dirty flag makes stepping cheaper, hashing incremental and resync partial. That lets the island grow several-fold before Boogle needs workers or a new architecture. Until playtests show a bigger grid or more than six players, rows 1-4 of the table are the whole job.
