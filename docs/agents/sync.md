Before choosing or changing any state or event delivery, read this sync contract.

## Pick a sync kind for each piece of state
Cheapest that works (table: DESIGN.md, "Pick how each feature shares state"). Physics is never Lockstep.
- **Local** (only this tab sees it, or it decorates): no API. Floats, `Math.random()`, GPU, all fine.
- **Owner** (one player drives it; physics): `addPresenceField(key, getter)` + `onRemotePresence((r, pr, time) => ...)` (`src/netplay/net.ts`), smoothed with `createSnaps()` (`src/netplay/snaps.ts`, sample at `now - INTERP_MS`). 20 Hz, latest wins: a few numbers under an untaken key that names the feature (`boogler`, not `b`; existing short keys stay as they are; taken keys: `npm run registry -- --json`). A peer that leaves just drops out of `remotes`: sweep your per-remote meshes.
- **Owner that changes hands** (one shared physics object any tab may simulate): `createOwnerSync(state, object)` (`src/netplay/owner-sync.ts`) has the claim rule, the orphan pick, the mode flip and the sampling; the object keeps its presence key and wire shape, and what holding means. Example: the ball (`src/entities/ball/`).
- **Host** (shared, small, changing; restarts with the next host): `addHostField(key, getter, onValue)`. Example: The Boogler.
- **Server** (replication, docs/plans/replication.md; railway and rail tuning): the server applies actions on arrival and replicates the components that changed (`src/world/railway-server.ts`, `src/world/railway-replicate.ts`); clients read a mirror (`src/adapters/railway-*.ts`) and, since R1b, predict their own actions with the same rule (`src/world/railway-predict.ts`): effects play on the press from the prediction, never again on the server's confirmation, and a refusal or lost race comes back as `onCorrected` for a physical return. Thresholds (a bill completing, the forge lighting) stay the server's. New shared state waits for R3's general API; don't add a lockstep op to a Server-kind state.
- **Lockstep** (shared grid or many cells, persists): recipe in [src/world/rules/README.md](../../src/world/rules/README.md): `src/sim/<x>.ts` + test, `src/world/rules/<x>.ts` (ops, state, ticks; exports `edits` and optionally `invariants` for `test/world-replay.test.ts`; bump `WORLD_NS` for a development saved-shape break, with no migration; host-only facts for validate via `setEnv` → `ctx.env`), one appended line in `rules/index.ts`, its API in `Rules` in `rules/types.ts`, and a `src/features/<x>.ts` adapter (`submitEdit`, `onApplied`, `onAfterTick`, `onSnapshot`). Example: piles (`rules/piles.ts`, `src/adapters/piles.ts`). Sync contract: [src/world/README.md](../../src/world/README.md).
- **One-off events** (a honk, a ping) are messages, not state: `onRoomReady(room => room.onMessage(...))`, `room.send(msg)` (reliable, ordered, every other peer; validate and rate-limit on receipt). Examples: `src/features/ping.ts` (each ping an entity), `src/features/honk.ts`. Room interface: [src/net/README.md](../../src/net/README.md); never the WebSocket directly.
