Before choosing or changing any state or event delivery, read this sync contract.

## Pick a sync kind for each piece of state
Choose the cheapest of three kinds: Local, Owner or Server. No lockstep state remains since v40; v44 removes the lead tab and Host fields. The owner-controlled DESIGN.md table has its replacement drafted in [players step 8](../plans/server-owned-players-step8-report.md).
- **Local** (only this tab sees it, or it decorates): no API. Floats, `Math.random()`, GPU, all fine.
- **Owner** (one player drives it; physics): `addPresenceField(key, getter)` + `onRemotePresence((r, pr, time) => ...)` (`src/netplay/net.ts`), smoothed with `createSnaps()` (`src/netplay/snaps.ts`, sample at `now - INTERP_MS`). 20 Hz, latest wins: a few numbers under an untaken key that names the feature (`boogler`, not `b`; existing short keys stay as they are; taken keys: `npm run registry -- --json`). A peer that leaves just drops out of `remotes`: sweep your per-remote meshes.
- **Owner that changes hands** (one shared physics object any tab may simulate): `createOwnerSync(state, object)` (`src/netplay/owner-sync.ts`) has the claim rule, the orphan pick, the mode flip and the sampling; the object keeps its presence key and wire shape, and what holding means. Example: the ball (`src/entities/ball/`).
- **Server** (railway, rail tuning, roster, seats and The Boogler): the server applies authenticated commands on arrival and replicates changed components (`src/world/railway-server.ts`, `src/world/server-ops.ts`). Clients read complete mirrors (`src/adapters/railway-*.ts`) and may predict declared actions with shared rules (`src/world/railway-predict.ts`): effects play on the press from prediction, never again on confirmation; refusals and lost races use `onCorrected` for a physical return. Thresholds stay the server's. Roster and tune commits wait for a durable checkpoint. Transient seats predict sit/stand and reconcile each second; pose stays Owner. The Boogler publishes legs on decisions, saves his position/facing and shares accepted present/puff reactions as server events. Registration/projection contract: [src/world/rules/README.md](../../src/world/rules/README.md); clock/checkpoint contract: [src/world/README.md](../../src/world/README.md). New state uses this boundary; clients do not hash or simulate shared ticks. A client predicting nothing is conformant.
- **One-off events** (a honk, a ping) are messages, not state: `onRoomReady(room => room.onMessage(...))`, `room.send(msg)` (reliable, ordered, every other peer; validate and rate-limit on receipt). Examples: `src/features/ping.ts` (each ping an entity), `src/features/honk.ts`. Room interface: [src/net/README.md](../../src/net/README.md); never the WebSocket directly.

Effective prototype pages keep Local unarbitrated seats and a separate Boogler per tab. The retired `?proto=place` alias still opens the production game and uses Server authority. They do not acquire a server command session for those features. The same Local fallback applies when no session exists; an established production session that disconnects instead retains its reconnect/reconcile behavior.
