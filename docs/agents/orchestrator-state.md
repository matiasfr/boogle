## Rules learned

The lessons; the orchestrator keeps them.

1. A shared rule constant the server checks (a reach point, a position) is a mixed-build change even with no op or state change: the web client deploys in minutes and the server in about 20, so players are refused meanwhile (18 November: the forge rack's move refused `rail.forgeTake` 47 times until the server landed). Say so in the ship, or ship the server side first.
2. Never run `ship-queue` through `| tail`: it hides the exit code. Log to a file, grep narrowly (`ship-check|error|rejected`).
3. A test that spawns git under the pre-push hook inherits `GIT_DIR` (fixed in #1601: `test/helpers/scratch-git.ts`). If every worktree says "this operation must be run in a work tree", check `git config core.bare`.
4. A rebased branch is pushed under a new name, never force-pushed. A branch with merge commits can't be rebased by `ship-branch`: squash it onto origin/main on a new branch.
5. About three full-suite agents is a machine's limit (the Mac's, measured; HOTBOX's is untested); briefs ask for typecheck, lint and touched tests only. HOTBOX: three looks at once, at most two of them real-speed, timed or two-player; a frame-time reading runs alone ([25 November](../decisions-process.md#d-2026-11-25-three-looks-on-hotbox)).
6. Default shell is Node 24: export Node 26 (`$HOME/.nvm/versions/node/v26.13.0/bin` on the Mac, `$HOME/AppData/Local/nvm/v26.13.0` on HOTBOX). Run focused tests with `UNIT_ONLY="<file> <file>" node dev/test-unit.ts` (space-separated; a comma list reads as one file name) (a bare file argument is ignored and runs the whole suite, about 8 minutes on HOTBOX; found 18 November), not `npx vitest`.
7. Keep independent reviewers: they found real defects in batch C, the CI diet and ring2 R1–R2.
8. New test files need review and must fit the [test diet](tests.md#tests); briefs say "no new unit test files" unless the code is lockstep, even when the plan's step names one (garage step 2, 17 November: a review round to delete it).
9. The registry's 14,000-character must-read budget per route is nearly full: an edit to `tests.md` or `sync.md` must not grow them.
10. A solo look warps page time about 12x while the server runs at real speed: evals wait on server ticks (`railAt()`). Two-player warp looks need `--warp-speed 2`.
11. `refs/stash` is shared across worktrees: no `git stash` in any brief. Two ships fetching at once fail with "cannot lock ref"; rerun.
12. After a ship that changes startup loading, load https://boogle.club/ before calling the site healthy (`dev/live-boot.ts` guards it). During a GitHub Actions outage, run CI locally and merge by PR ([owner call](owner-calls.md)).
13. An artifact page must copy what its store returns before mutating it: the store's objects are read-only and a write fails silently (the open-calls page lost answers this way). Do not republish a page while the owner is using it.
14. A proof gate for anything touching line 2's trains must include the footing wagon's arrival trip by trip and every footing delivery tick; a gate on stage ticks and lever waits missed a cumulative wagon delay.
15. A rule change that moves pinned fixtures needs its own WORLD_NS bump even when the save shape is unchanged.
16. Give a peer or agent the plan text on a pushed branch before asking it to build to a ruling; HOTBOX built two steps from a chat summary and had to reconcile.
17. Before telling the owner he played, check the room: a tab the orchestrator left open on boogle.club logs as play sessions under the default name (the `freight-running-gm82nj` sessions on 12 November were the orchestrator's pane). The orchestrator's own browser checks log the same way.
18. The owner's earlier words are often in `docs/brainstorms` and `docs/plans/town-layout.md` under his own term (he says "rotunda" for the Roundhouse): search those before saying something is not in the plan.
19. A probe that copies a test's fuzz must reproduce the test's own printed figures and ask rate before its numbers are used (HOTBOX's probe threw away two asks in three and every wait figure for a day was low).
20. A bound proven on a test's own seeds is not proven: try 24 to 48 seeds and the long length before telling the owner a limit holds. Leg 1's 1,400 held on four seeds and is 1,553 on 48.
21. When a gate fails, the designer restates it only where it measured the wrong thing; after two rounds the question goes to the owner as a choice.
22. An agent must not edit files while its bot run is in flight (the edit reloads the page under the bot). Read a bot run's `verdict.json` yourself rather than waiting for the agent to say.
23. A rule test that calls `apply()` proves the rule, not the path: every new op needs a host test that sends it as a real `r:edit` (the server stripped `leg` and `id` from three v32 ops and nothing noticed until a reviewer pressed the prompts). A review of sim or server code drives a real server at least once.
24. Reviewers must exercise what the builder did not: dwell before acting, press every prompt, walk every stair, hold a phone upright. Each of today's blockers was outside the builder's own captures.
25. A hidden browser pane has zero size and the game waits for a drawable size: give the pane a size (`resize_window`) before judging a boot slow.
26. A smoke failure on the server's source commit right after a server-path merge is usually the race with `deploy-server.yml` (19 minutes on 17 November; smoke waits 24 since then): check that the deploy finished and `/version` shows the commit, then rerun the smoke.
27. A change to label or layout costs must be diffed against main for the states most rooms are in (the pre-rivet maps), not only the new state.
28. After a ship lands, the next queued branch was checked against the old main. When two branches touch neighbouring code (v45 renamed a helper the meadow used), re-run `node dev/ship-check.ts origin/main HEAD` on the second after the first lands, before shipping it.

## How merging works

`npm run ship-queue -- <worktree> --wait [--reviewed "<stamp> <who, what they found>"]`, in the background, one branch after another ([orchestrate-boogle skill](../../.claude/skills/orchestrate-boogle/SKILL.md), "Merge"). The gate prints the stamp it needs. It finds Node 26 itself. Keep merging while the owner plays; only a `WORLD_NS` bump waits while they are mid-session (owner, 9 November).

On the Mac `../boogle-trusted/node_modules` symlinks to the main checkout's node_modules, and an `npm ci` there empties it; on HOTBOX it is its own install. Reinstall with `npm ci` in the main checkout if `node dev/playtest/cli.ts` can't find playwright.

Every code change ships only after an independent review; docs-only changes ship with `--orchestrator-read`. Do not ship code with `--orchestrator-read` (the 14 November slip is in [the log](orchestrator-log.md#process-14-november)).

The Codex sandbox cannot launch a browser: the orchestrator runs `npm run test:net` in the job worktree itself; do not treat a sandbox launch failure as a network regression. The B4 outside-sandbox run was 190/190, as was rotunda 1a's reported run.
