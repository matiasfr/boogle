# Many meshes, lights or post passes; count diagnostics

- `npm run perf`: before/after adding many meshes, lights or post passes. Not for UI, tuning or a single prop. Its numbers mean something only while no other agent is rendering on the same machine.
- `npm run counts`: draw calls, shadow draws, programs and first-load gzip as JSON; `counts-nightly.yml` keeps one a night from SwiftShader. Counts only: no times, no budget yet.
- `npm run bench` (dev/look/bench.ts): the benchmark the daily perf job runs. A visible Chromium on the Mac GPU, the current game at 1280x800, DPR 2. Six poses (spawn, town, forge and line 2, a far view over Place to the classic island, the classic island close, mid-play with a second player, walking and dust): draw calls, triangles, shadow calls, programs, materials, shadow casters and GPU bytes, then 5 s of real frames: CPU and GPU ms per frame, CPU by subsystem (render, physics, room clock and replication, view updates), heap and allocation per frame. Also a production build: bundle bytes, a cold first load (bytes, time to "Jump in") and the asset budget (25 MB first load, 100 MB in all, 4 MB per asset). `--root <checkout>` measures another commit (a `git archive` with this checkout's node_modules symlinked; it serves that commit's game and server), `--poses spawn,far`, `--no-load`, `--query classic=1`, `--dpr 1`. Its page is cross-origin isolated (5 µs timers) by `coi=1`, which the dev server answers with the headers; before 7 November a Playwright route set them, which kept the page's railway room from connecting. About two minutes; numbers hold only on a quiet machine. GPU times vary about 10 % run to run; triangles and calls are exact.
- `npm run daily -- perf` runs it every night on origin/main ([daily jobs](../../../dev/daily/README.md)) and comments on the Performance issue: regressions against the median of the last three valid runs (thresholds in `PERF_POLICY`, dev/daily/perf.ts), budgets and the commit range. History: `~/.boogle/daily/perf/history.jsonl` on the owner's Mac and the issue's comments (`gh issue view --comments` on the issue labelled `performance`). `-- --local` runs it on your checkout without GitHub or history. Findings and recommendations: [performance research](../../research/performance.md).
