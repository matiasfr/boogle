# Many meshes, lights or post passes; count diagnostics

- `npm run perf`: before/after adding many meshes, lights or post passes. Not for UI, tuning or a single prop. Its numbers mean something only while no other agent is rendering on the same machine.
- `npm run counts`: draw calls, shadow draws, programs and first-load gzip as JSON; `counts-nightly.yml` keeps one a night from SwiftShader. Counts only: no times, no budget yet.
- `npm run assets -- --check` (in `npm run check`) only warns on asset size: an asset over 4 MB, a texture over 2048 px, first load over 25 MB or total over 100 MB print a warning and a closing count, and never fail the check (owner, 10 November).
- `npm run bench` (dev/look/bench.ts): the benchmark the daily perf job runs. A visible Chromium on the Mac GPU, the current game at 1280x800, DPR 2. Six poses (spawn, town, forge and line 2, a far view over Place to the classic island, the classic island close, mid-play with a second player, walking and dust): draw calls, triangles, shadow calls, programs, materials, shadow casters and GPU bytes, then 5 s of real frames: CPU and GPU ms per frame, CPU by subsystem (render, physics, room clock and replication, view updates), heap and allocation per frame. Also a production build: bundle bytes, a cold first load (bytes, time to "Jump in") and the asset budget (25 MB first load, 100 MB in all, 4 MB per asset; reported against, and guidance until the owner calls the performance pass: [owner call](../owner-calls.md#performance-guides-not-gates)). `--root <checkout>` measures another commit (a `git archive` with this checkout's node_modules symlinked; it serves that commit's game and server), `--poses spawn,far`, `--no-load`, `--query classic=1`, `--dpr 1`, `--size 375x812` (with `--query 'q=mobile&dev=1&graphics=msaa:false'`, the phone profile: a phone's viewport, water quality and MSAA default on the Mac's GPU; `graphics=id:value,...` sets Dev graphics overrides, e.g. a `detail` rung). `--rail-seed q6-done --poses pier,head` stands the player on the pier deck facing open sea and on Far Head (opt-in poses; the seed is written by the measured checkout's own `dev/look/rail-seed.ts`, so it works with `--root`). `--cpu-prof <prefix>` saves 5 s of Chrome's sampling profiler at each pose, after its timing, as `<prefix>-<pose>.cpuprofile` with the frames it spanned: where main-thread time a frame goes, to compare builds by function. Each pose lists GPU ms per pass by render target (`passes`; on Apple GPUs passes overlap, so they don't add up to the frame's span: ablate with `graphics=` to price one) and the run records the load average before and after. `--scaler 40,60` leaves adaptive resolution on and watches the scaler's ratio and detail rung through 40 s of a pixel-scaled frame cost (`--scaler-k`, ms at full resolution) and 60 s after it. Its page is cross-origin isolated (5 µs timers) by `coi=1`, which the dev server answers with the headers; before 7 November a Playwright route set them, which kept the page's railway room from connecting. About two minutes; numbers hold only on a quiet machine. GPU times vary about 10 % run to run; triangles and calls are exact.
- `npm run daily -- perf` runs it every night on origin/main ([daily jobs](../../../dev/daily/README.md)). It holds the machine bot slot for the whole measurement and first waits up to 30 minutes for a 1-minute load of at most 6 and no other harness Chromium (`PERF_POLICY.quiet`); a night that never gets quiet is reported as `skipped: machine busy (load N)` and measures nothing, and a measured run states its load before and after. It comments on the Performance issue: regressions against the median of the last three valid runs (thresholds in `PERF_POLICY`, dev/daily/perf.ts), budgets and the commit range. History: `~/.boogle/daily/perf/history.jsonl` on the owner's Mac and the issue's comments (`gh issue view --comments` on the issue labelled `performance`). `-- --local` runs it on your checkout without GitHub or history. Findings and recommendations: [performance research](../../research/performance.md).
