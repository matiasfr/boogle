# Any harness run; networking or render-pipeline changes

- Every harness run is WebGPU (SwiftShader over Vulkan on Linux and CI, Metal on a Mac; `?dpr=fixed`). A `gfx errors` line with entries is a bug.
- Rendered `smoke` runs against the live site daily on the owner's Mac (`dev/daily/jobs.ts`), including ball handover and same-tick hashes. CI `smoke.yml` uses the browserless Node asset/version/room probe after deploys and nightly, then `dev/live-boot.ts` loads the live game once in headless Chromium and fails when startup throws after WebGPU came up (a missing WebGPU on the runner only warns, boot unproven); failure opens a `smoke` issue. `npm run ship -- --gpu` (or `npm run check:gpu`) also runs the rendered scenario on a Mac before shipping: do that for networking or render-pipeline changes, not every ship.
