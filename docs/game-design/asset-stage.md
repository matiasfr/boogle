# Asset and animation stage

`/character/` browses and inspects built and code-generated assets without an island, room, physics or game features. `/assets/` redirects here, retaining query parameters. All selection, filtering, thumbnails, camera, lighting and playback state is Local to this document. The catalogue comes from the build manifest, actual mesh-bearing GLB nodes and side-effect-free code descriptors. The current set has 51 cards: seven built roots, 32 kit parts and twelve code previews.

Browse the thumbnail grid with a name/source search and type filter (characters, kit, nature, props, buildings, POIs). Each native link opens its asset on the stage; Tab/Enter and touch work, and modified clicks can open a separate tab. Every card has a direct URL, source badge, triangle and authored-clip counts, and build warning text. Code triangle counts are measured when a visible thumbnail or stage preview is created; pending counts show an ellipsis. Filtering to no results leaves the current stage selection intact. The catalogue scrolls within a bounded pane; animation, overlays, lighting, detailed metrics and sharing collapse independently. Phone width keeps the stage above a bounded panel.

Thumbnails render only as cards enter the visible grid, through the existing stage WebGPU renderer into a 112-pixel offscreen target. A serialized queue and document-local cache (up to 96 entries) reuse them. Reload discards the cache, so changed source cannot leave a persistent stale thumbnail. No thumbnail binaries, capture pipeline or additional first-load image downloads are added. Failed thumbnails have a labelled fallback and do not prevent opening the asset. Every descriptor exposes `reviewStatus: 'unreviewed'` for a future review inbox; there are no review controls or automation.

Other kit parts retain their distinct materials, grain and moving pivots. These runtime joins leave the source GLBs and the stage's named-part catalogue unchanged.

The [two-asset authoring trial](../research/asset-model-trial.md) adds a feeder roller and a separate conductor cap to the catalogue. The roller retains its axle-centred origin; only its stage holder is lifted 0.075 m above the floor. Buddy's Hat selector adds **Conductor trial** (`hat=conductor`), rigidly attached to the existing Head bone on cloned preview instances. Its paintedToy and deliberately brass-tinted steel materials are owned clones. Buddy's production source, rig, wardrobe and gameplay remain unchanged. The independent cap card inspects the Head-relative asset; use the Buddy hat selector for worn clips. Resident Buddy preview counts include the hidden trial cap, as they already include other hidden wear parts.

The viewport has mouse/touch orbit, pan and zoom, turntable, a one-metre grid, bounds/dimensions and an actual Buddy for scale. Wireframe, bones, named hand/back socket axes and authored local root/pelvis trajectory are optional. Hero-clips has no meshes and shows its skeleton. Root trajectory never includes camera motion; the character library is in place.

Every clip has a duration. Play/pause, loop, speed, scrub, numeric seconds, reset and frame-step controls use **30 Hz preview sampling**, not a claim about native glTF FPS. Exact endpoint seeks hold the final pose. Buddy Raw plays the real retargeted clip without body blending/life; the hero-clips entry shows the original skeleton. As played uses the same production body rig, retargeter and procedural life functions, driven by movement inputs chosen from the clip and the selected carry/hold/seated/airborne pose. Seek resets the clock, blink seed and state, then replays 30 Hz steps and any exact remainder. Playback advances the state without rebuilding it. This is a body preview, not a physics or game input replay.

Legacy clip/t/view/pose/hat/spin/crowd/blink links work. A carrying pose without cargo or amount keeps the original loaded lean and arm pose without showing cargo; an explicit amount uses that load instead, including zero. Legacy hop selects an airborne body pose at its supplied time; it is not a physical jump simulator. Copy this view records asset, part, clip, time, speed, loop, playback mode, pose, hat, camera position/target/FOV, turntable angle, light and overlays. For example: `/character/?asset=scaffold-kit&node=plank&clip=drop&t=0.1&view=Three`, or `/character/?asset=buddy&clip=Walk_Loop&mode=played&pose=carrying&t=0.4`. The selectable URL field is a fallback when clipboard access is unavailable.

Buddy's **Local gear and cargo** panel works in Raw and As played. `gear=all` enables every worn item; `rings`, `spool`, `glider`, `frame` and `canopy` accept individual `0`/`1` overrides. `cargo=logs|rails|stone|beam|boiler` and `amount` select the load; amounts clamp to the game's real capacity (8 ordinary pieces without the frame, 16 with it, or one beam/boiler). Choosing cargo selects the carrying pose. The Local body colour selector uses the production palette or the authored colour. `bodyColor=auto` defaults to game yellow when gear/cargo is visible; `bodyColor=authored` preserves the asset colour, and a palette hex (for example `bodyColor=%23ffc23d`) pins a colour. Gameplay can restore another saved colour or randomly choose one, so yellow is this review default. Copy this view records colour, each toggle and the cargo/count. Combined review example: `/character/?asset=buddy&gear=all&bodyColor=%23ffc23d&cargo=logs&amount=16&mode=played&pose=carrying&clip=Walk_Loop&t=0.4&cam=2,1.4,-3&target=0,0.8,0&reference=0&bounds=0`. Fitted bounds count only visible geometry and occupied cargo instances. The canopy uses the production shape and full-open pose; opening/closing travel is not simulated here.

Neutral studio uses linear HDR → Neutral → sRGB. The legacy Shipped frozen sky uses the actual atmosphere/cube, sun direction and sampled irradiance at .24, and AgX. **Production Neutral** uses that same sky with the current Place Neutral output. Review exposure is adjustable and saved in the link; preset defaults are 1 for studio and .16 for both sky presets. It stays fixed for reproducibility: adaptive exposure, world fog, underwater effects and bloom are excluded and labelled. All use the shared runtime loader/material conversion, including Meshopt and KTX2 support, and one standalone WebGPU renderer/pipeline. Axe comparisons can select `sparkle=round` for the old dots; the normal summon uses the production glint emitter.

The inspector counts triangles, vertices, material slots, unique geometry and texture dimensions/formats; hidden authored wear parts are included. Draw calls are measured from the completed stage render and include floor/reference/helpers, shadows and output. Estimated GPU bytes include geometry buffers and texture mip allocations (actual transcoded compressed mip byte lengths when available), exclude render targets/driver overhead and remain unknown when the texture allocation cannot be inferred. These are not device VRAM measurements.

The generated catalogue checks source-plus-sidecar/output hashes, actual output byte budgets and expected clips at serve/build time. Defaults remain 1 MiB per asset and 12 MiB total downloads; sidecar overrides apply. Rebuild/reload after editing assets. Replaced preview mixers, materials and helpers are disposed, and the document owns its loader/sky lifetime. Two-version comparison is deferred; this version offers reproducible single-view links and Raw/As played comparison.

## Agent motion review

Buddy's Local panel also selects `axe=starter|multi|proper|proper-multi` (or `none`) and
`chop=bite|rebound|full` (or `off`). Axe inspection uses As played so the real production
rig adapter and coordinate frame apply. Copy this view retains these controls, the Local
`reducedMotion=1` preference and `trunkDistance` (default 1.35 m). Full-back selection fills
the current capacity unless the URL explicitly supplies `amount`; use `frame=1&amount=16`
for the full worn-frame case. `chop=off` removes the trunk for unobstructed front, side,
back and three-quarter proportion views. The reference cylinder has 0.4 m radius; its
distance slider moves the inspection reference only, exposing reach limits rather than
moving or stretching Buddy. It is not a copy of every tapered/ridged game tree.

Example: `/character/?asset=buddy&axe=proper-multi&chop=bite&mode=played&frame=1&cargo=logs&amount=16&play=1&cam=3,1.8,3&target=0,0.9,0.4&reference=0&bounds=0`.
The stage and game share `axe-models.ts`, `chop-timing.ts` and `chop-motion.ts`; the stage
does not maintain a second swing. Each 0.90 s preview includes anticipation, contact and
recovery. The game's next press may restart after 0.24 s; the preview clock does not change
that cadence. Pose endpoint seeks preserve the endpoint rather than wrapping early.

`node dev/look/asset-motion.ts --broker --asset buddy --axe proper-multi --chop full --frame 1 --cargo logs --amount 16 --name axe-full`
records the production pose. `--reduced-motion 1` exercises the Local preference and
`--trunk-distance 3.2` exposes the outer interaction-distance mismatch. Curves include
both wrist-bone distances to the handle centreline (the mitten extends beyond its wrist),
the leading cutting-edge position and radial trunk error, plus shaft proximity to posed
torso/head triangles. Unsigned distances and signed nearest-face candidates are distinct:
open head/torso subsets can produce negative signed readings for a shaft outside the body.
The frame/cargo remains visible for inspection but is not included in this clearance proof.

`.look/axe-chop/` and linked broker evidence. Art approval and real-time feel remain the
owner's check; no capture score approves the swing.

The stage owns the measurements and frame IDs. The background game's player curves are not asset curves. A run retains successive completed canvas renders, a lower-rate view across the cycle, the wall-time video, numeric samples and frame-numbered diagnostic outliers. Camera, playback selection, source provenance and capture timing accompany the evidence. Keep the camera fixed, disable the turntable and use normal speed. A render ID is not a monitor presentation timestamp; encoded video may repeat or drop stage frames, and collection overhead affects timing.

Motion declarations distinguish clips, bone attachments, procedural motion and explicit `none`. Use shared production formulas for actual moving parts. Feeder rollers are currently static in both the place kit and greybox game implementations; their axle review uses an explicitly labelled diagnostic spin, not an invented gameplay rate. A static asset without that requested probe reports no motion. Buddy's Raw mode samples retargeted authored clips; As played exercises production body/life layers. Jump clips supply real airborne body inputs while the preview remains at floor height; cargo is drawn using the production layout, but jump travel, pickups, pouring and physical cargo contacts are not simulated.

For gear clearance use, for example, `node dev/look/asset-motion.ts --broker --asset buddy --clip Walk_Loop --mode played --gear all --cargo logs --amount 16 --pose carrying --attachment ring-left --name loaded-ring`. Attachment targets are `ring-left`, `ring-right`, `spool`, `glider` and `frame`; calf/forearm bones and the spine-driven load socket are measured on the visible preview. `--canopy 1` opens the canopy. Hidden gear/cargo is excluded from body-surface comparisons; the full posed body remains eligible even when an attachment sits more than 0.15 m away.

For attachments, inspect bone-relative translation and rotation plus clearance against the posed body mesh. For clips, inspect bone rotation and root-position changes, with loop boundaries identified separately. For rotating parts, inspect rate, pivot and axis stability. Threshold crossings identify frames to look at, never acceptance. Preserve failed evidence before one targeted repair and repeat the affected capture. The accepted Buddy Walk_Loop is a useful control for interpreting ordinary motion. The agent opens sheets and reports observed frames; the owner retains the final visual check. Display smoothness, device performance, physical cargo clearance and world placement require their own evidence.
