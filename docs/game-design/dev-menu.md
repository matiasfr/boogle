# Dev menu

Open `?dev=1&water=new` once per browser/origin. Dev stays enabled across reloads, builds and rooms; nothing is shared with friends or another device. `tune=1` also opens the dock for that visit without enabling remembered Dev. `?dev=0` and **Turn Dev off** override storage, clear only Dev/Water/Looks preview preferences and the disposable launch marker, release input/camera, and reload without debug instrumentation. Game saves and identity remain. Unsupported preference fields are discarded while enablement survives.

The always-visible DEV strip shows the build, Free cam, Return while flying, Go to, Report, Tools, Play and Off. Report copies immediately, with visible status and a selectable-text fallback. All nine tools live in a non-modal dock: left, right, bottom or collapsed, remembered locally. Desktop side docks are at most 300 CSS px wide, with short Water / Go to / Camera / Inspect / Perf / Room / Report / Tests / Looks tabs and exactly one mounted panel. Tools opens the remembered supported tab or Water. A compact position selector and Collapse remain above it. Info/More holds prose, diagnostics and rare actions; unavailable actions and mutation restrictions stay visible. No backdrop or room pause. Phone/coarse-pointer layouts use a tool selector in the same header row, a short bottom sheet, safe areas and 44 px controls; camera buttons stay outside. Typing/dragging consumes avatar input; clicking or tapping the scene restores game focus. **Play · ` for mouse** closes the dock, returns the camera and takes pointer lock when supported. ` (the tilde key) frees the mouse and keeps it free (scene clicks don't re-lock) until pressed again, which takes the lock back; Esc also releases the mouse without opening Pause, but a second Esc opens Pause; Menu still opens Pause, whose Dev entry opens the dock.

Go to contains a compact picker for Starting area, Lower home island and Current home island, plus a shore view for each, followed by Open. These are explicitly separate pages with a reload. Links retain Dev, Water/sky/tone/time appearance flags and saved settings, discard fixture authority, and use `classic=1&island=low&room=island-low` for the lower island. Shore entries move only the camera and consume the one-shot URL destination, so a later reload returns to the player camera. A separate player-destination picker offers Start test / Go / Return with the disposable-run restriction; island reloads never grant player teleport authority.

1. **Water** mounts the production-water panel in the dock. Fresh groups start collapsed. Search matches group names, labels and binding keys, temporarily expanding results without changing remembered open groups. Each individual control has a star to move its live row into Pinned at the top; known pinned keys and open-group names persist in `boogle.dev.water-ui.v1`, while search stays transient. Numeric controls place label, range and number inline; colors and bloom enable remain native controls, and AgX look selection stays in Post. Only changed bindings show a small reset; group/global resets under More skip unchanged setters. Changed counts remain visible. More holds explanatory copy, rare Quality controls, copy/paste and unavailable controls. Both Dev and `tune=1` visits create editable uniforms at load and use this dock. Legacy-water visits offer **Reload with tuning**. Edits auto-save; closing/switching/collapsing retains appearance, and Dev/tuning visits restore supported settings even when collapsed unless a named Look takes precedence. Unsupported saved keys/values are dropped; explicit pasted JSON stays strict, including bloom's 0/1 toggle. Off clears the exact Water UI key alongside Dev-owned appearance preferences.
2. **Go to** offers spawn, shore, shallow/deep water, a 30 m big-fall plunge, tower, Far Head, forge and the current construction frame, plus Return. Place layout/terrain and current frame supply the positions. Landings require finite in-bounds coordinates, walkable static support and clearance; sea entries require suitable depth. No stage is advanced to make travel work. Return retains the first validated origin until used. Carried items, pair grips and unsupported vehicle states must be put down/exited first; seat, hook/glide, input, platform carry, velocity and cached water query are cleared before movement.
3. **Free camera** is a global Local session toggle, independent of dock/tool visibility. Scene drag looks; WASD moves, Space/Shift moves up/down, held touch buttons move, and pad sticks move/look with LB/RB down/up and B Return. Speed is adjustable. It suppresses avatar movement/actions before gameplay input runs, clears held input on blur, and restores the saved camera pose/FOV on Return/Off/leaving. Friends see the ordinary avatar at its physical location; the body may still be affected by normal physics. Camera commands never teleport it. Named viewpoints and six saved, validated route-specific bookmarks are available; live camera state is never saved. Home player teleport remains unavailable outside the disposable solo place contract.
4. **Inspect** samples entity costs/counts, player/place state, water runtime and synchronous water body/query validity/age only while shown. Optional outlines show at most 64 nearby static box/sphere colliders and decks within 30 m. Heightfields and moving platforms are not outlined. No GPU readback is enabled by inspection. Closing removes sampling and geometry.
5. **Performance and startup** reads the existing CPU window, copies data and runs the existing five-second hardware measurement when `prof=1` was enabled at load. Reload buttons enable profiling/startup or disable capture. Unsupported GPU values and actual presentation time stay unavailable; reload does not establish a cold Metal cache.
6. **Room health** reads connection, transport, local lead status, observed builds, queue/drop/hash status and the separate temporary place authority. Unexposed rejection and remote-lead identifiers are labelled unavailable. It sends no diagnostic messages and never claims place snapshots are Lockstep-verified.
7. **Copy test report** includes build, world namespace, effective flags, fixture version/id, player/camera pose, loaded tool settings, inspection, room health and the last 40 command outcomes. Clipboard failure leaves selectable text and a JSON download. PNG download captures the existing game canvas, excluding menu DOM. The setup link carries named scenario/destination, build/version and allow-listed appearance flags; tuning values remain in the report. Reopening a setup asks before starting a disposable run and warns on build mismatch. It is not exact world replay. Existing `record=1` input trace controls remain optional and are not a complete world snapshot.
8. **Test scenarios** starts fresh, fresh walking (no stage skip), first path, line 2, tower, Far Head or trains through the existing place setup handlers. Every Start creates a fresh random room with explicit `proto=place&coop=0&fresh=1`, a matching session launch marker and a persistent **TEST** badge. Saves remain scoped to that room. No item/resource grant command, broad save clearing or shared reset is exposed.

Player movement and stage setup recheck the disposable route/version/marker, exact room, initialized player and absence of other room peers at execution time. A room prefix, `coop=0` or client flag alone is not authorization. This is accidental-collision isolation, not server-enforced privacy or test capability. If another peer joins, mutations are refused. Existing legacy prototype globals are unchanged and are not certified by this gate.

**Sync kinds:** dock, camera, preferences, tools and reports are Local; tester movement is Owner; stage setup is prototype-local in a disposable solo place run. There are no new wire operations, Host mutations or Lockstep writes. Without explicit or remembered opt-in, the tiny eager gate imports no Dev chunk/CSS and creates no Dev DOM, entity, sampler or frame hook. Normal invite links carry only the room and strip all Dev/debug flags; deliberate setup links retain explicit opt-in.

**Agent API:** `boogle.dev.tools()`, `open(tool?)`, `run(tool, command, args?)`, `snapshot()` and `close()` use the same bounded tool descriptors and result path as the UI. Tool ids are `water`, `destinations`, `camera`, `inspect`, `performance`, `room`, `report`, `scenarios`, `looks`. No arbitrary scripting or property setter is provided.

## Looks

**Looks** registers a ninth dock tool on Dev/tuning visits. On `water=new` it compares five one-click presets on the procedural frozen sky: **Current** (production metered Neutral, owner call 4 November), **Clean toys** (metered Neutral with a brighter trim), **Sunny toys** (AgX with an 8% highlight-protected display-linear midtone chroma lift), **AgX Punchy** (the Post panel's 1.35 power / 1.4 saturation), and **Sunshine water** (Clean toys plus the water retune). Toy sky is unsupported here. Current always uses trim 1; candidate exposure trims are recorded in EV and can be adjusted. The initial Clean/Sunshine trim is `1 / 0.771116` (about +0.375 EV); Sunny/Punchy start at 0 EV.

Choose A and B, then press **A/B** or **backslash** while the Looks panel is open. The same 44 px button works on touch. **Lock exposure** freezes the existing GPU meter history rather than replacing exposure with 1; unlocking resumes adaptation. The lock command samples its one-texel gain once for the copied record. Saved locks use the meter's initial settling frames on reload. Every curve is part of one prewarmed output shader, so selecting a look changes uniforms instead of compiling a pipeline. No extra scene pass, simulation or meter is created. The optional live tile board is deferred: the composed underwater HDR needs another target/pass, and Sunshine's water changes cannot be recovered from one shared image.

Selections, A/B slots, lock and candidate trims are Local in `boogle.dev.looks.v1`; a saved named Look is applied before the loading warm draw and takes precedence over older Water overrides. Opening Water does not reapply them. Selecting a look resets appearance bindings to their shipped defaults before its changes; device resolution stays separate. Water/Post edits remain usable and are marked **modified** in Looks. **Copy look** includes build, curve, lift, trim, lock/meter sample and effective water/post/light values, with selectable JSON if clipboard access fails. It does not change the game's default.

Sunshine uses saturation **1.1**, reflection gain **0.9**, reflection cap **0.8**, foam brightness **0.8**, glitter **0.6**, FFT energy **0.25**, absorption **[0.48, 0.055, 0.032]** and scatter **[0, 0.06, 0.1]** (linear RGB). The optical adjustment was compared against the sand with exposure locked; it uses the existing depth law, with no second tint. Existing FFT, shore, caustics and foam remain. Water's **Light fill** group offers bounded key/fill gain and tint on the existing frozen-sky sun/hemisphere, without a new light or sky rebake. A warm-key/cool-fill trial made no clear improvement over the procedural lighting in the inspected town/tree views, so the preset retains identity lighting controls. Compare manual light edits with exposure locked. Ordinary visits do not load the Looks module, create its uniforms, or alter their output graph.

The API uses `run('looks', 'select', {id})`, `slots` with `{a,b}`, `swap`, `lock` with `{locked}`, `trim` with `{ev}` (-2 to +2, candidates only), `settings`, and `copy`. IDs are `current`, `clean`, `sunny`, `punchy`, `sunshine`. A gated `lookPreset=<id>` reproduction URL selects without overwriting saved choice; it has no effect outside Dev/tuning visits.

`close()` collapses the dock without returning free cam. `registerDockPanel({ id, label, load })` from the lazy shell adds a panel before or after installation; `load()` returns `{ tool }`, whose `mount(parent, context)` returns a disposer. Optional `dispose()` releases session resources on removal/Off. The returned unregister callback removes the panel. Future comparison tools use this seam without a new shared switch.
