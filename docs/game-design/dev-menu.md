# Dev menu

Open `?dev=1&water=new&tune=1` once per browser/origin. Dev stays enabled across reloads, builds and rooms; nothing is shared with friends or another device. `?dev=0` and **Turn Dev off** override storage, clear only Dev/Water preview preferences and the disposable launch marker, release input/camera, and reload without debug instrumentation. Game saves and identity remain. Unsupported preference fields are discarded while enablement survives.

The always-visible DEV strip shows the build, Free cam, Return while flying, Report, Tools, Play and Off. All eight tools live in a non-modal dock: left, right, bottom or collapsed, remembered locally. No backdrop or room pause. Phone and coarse-pointer layouts use a short bottom sheet, safe areas and 44 px controls; camera buttons stay outside the sheet. Typing/dragging consumes avatar input; clicking the scene restores game focus. **Play · Esc for mouse** closes the dock, returns the camera and takes pointer lock when supported. Esc releases the mouse without opening Pause in Dev visits; the normal Menu button still opens Pause, whose Dev entry opens the dock.

Tools includes Starting area, Lower home island and Current home island, plus a shore view for each. These are explicitly separate pages with a reload. Links retain Dev and Water flags/settings, discard fixture authority, and use `classic=1&island=low&room=island-low` for the lower island. Shore entries move only the camera and consume the one-shot URL destination, so a later reload returns to the player camera.

1. **Water** mounts the shipped production-water panel in the dock. `&tune=1` without Dev still opens its standalone panel after the player enters. Editable shader uniforms are chosen at load, so Dev offers **Reload with tuning** when needed. Edits auto-save; closing/switching/collapsing the dock retains appearance, and tuning visits restore supported saved settings even when the dock is collapsed. Unsupported saved keys/values are dropped; explicit pasted JSON remains strict. Saved values apply only on tuning visits. No bloom or grade-comparison controls are added here.
2. **Go to** offers spawn, shore, shallow/deep water, a 30 m big-fall plunge, tower, Far Head, forge and the current construction frame, plus Return. Place layout/terrain and current frame supply the positions. Landings require finite in-bounds coordinates, walkable static support and clearance; sea entries require suitable depth. No stage is advanced to make travel work. Return retains the first validated origin until used. Carried items, pair grips and unsupported vehicle states must be put down/exited first; seat, hook/glide, input, platform carry, velocity and cached water query are cleared before movement.
3. **Free camera** is a global Local session toggle, independent of dock/tool visibility. Scene drag looks; WASD moves, Space/Shift moves up/down, held touch buttons move, and pad sticks move/look with LB/RB down/up and B Return. Speed is adjustable. It suppresses avatar movement/actions before gameplay input runs, clears held input on blur, and restores the saved camera pose/FOV on Return/Off/leaving. Friends see the ordinary avatar at its physical location; the body may still be affected by normal physics. Camera commands never teleport it. Named viewpoints and six saved, validated route-specific bookmarks are available; live camera state is never saved. Home player teleport remains unavailable outside the disposable solo place contract.
4. **Inspect** samples entity costs/counts, player/place state, water runtime and synchronous water body/query validity/age only while shown. Optional outlines show at most 64 nearby static box/sphere colliders and decks within 30 m. Heightfields and moving platforms are not outlined. No GPU readback is enabled by inspection. Closing removes sampling and geometry.
5. **Performance and startup** reads the existing CPU window, copies data and runs the existing five-second hardware measurement when `prof=1` was enabled at load. Reload buttons enable profiling/startup or disable capture. Unsupported GPU values and actual presentation time stay unavailable; reload does not establish a cold Metal cache.
6. **Room health** reads connection, transport, local lead status, observed builds, queue/drop/hash status and the separate temporary place authority. Unexposed rejection and remote-lead identifiers are labelled unavailable. It sends no diagnostic messages and never claims place snapshots are Lockstep-verified.
7. **Copy test report** includes build, world namespace, effective flags, fixture version/id, player/camera pose, loaded tool settings, inspection, room health and the last 40 command outcomes. Clipboard failure leaves selectable text and a JSON download. PNG download captures the existing game canvas, excluding menu DOM. The setup link carries named scenario/destination, build/version and allow-listed appearance flags; tuning values remain in the report. Reopening a setup asks before starting a disposable run and warns on build mismatch. It is not exact world replay. Existing `record=1` input trace controls remain optional and are not a complete world snapshot.
8. **Test scenarios** starts fresh, fresh walking (no stage skip), first path, line 2, tower, Far Head or trains through the existing place setup handlers. Every Start creates a fresh random room with explicit `proto=place&coop=0&fresh=1`, a matching session launch marker and a persistent **TEST** badge. Saves remain scoped to that room. No item/resource grant command, broad save clearing or shared reset is exposed.

Player movement and stage setup recheck the disposable route/version/marker, exact room, initialized player and absence of other room peers at execution time. A room prefix, `coop=0` or client flag alone is not authorization. This is accidental-collision isolation, not server-enforced privacy or test capability. If another peer joins, mutations are refused. Existing legacy prototype globals are unchanged and are not certified by this gate.

**Sync kinds:** dock, camera, preferences, tools and reports are Local; tester movement is Owner; stage setup is prototype-local in a disposable solo place run. There are no new wire operations, Host mutations or Lockstep writes. Without explicit or remembered opt-in, the tiny eager gate imports no Dev chunk/CSS and creates no Dev DOM, entity, sampler or frame hook. Normal invite links carry only the room and strip all Dev/debug flags; deliberate setup links retain explicit opt-in.

**Agent API:** `boogle.dev.tools()`, `open(tool?)`, `run(tool, command, args?)`, `snapshot()` and `close()` use the same bounded tool descriptors and result path as the UI. Tool ids are `water`, `destinations`, `camera`, `inspect`, `performance`, `room`, `report`, `scenarios`. No arbitrary scripting or property setter is provided.

`close()` collapses the dock without returning free cam. `registerDockPanel({ id, label, load })` from the lazy shell adds a panel before or after installation; `load()` returns `{ tool }`, whose `mount(parent, context)` returns a disposer. Optional `dispose()` releases session resources on removal/Off. The returned unregister callback removes the panel. Future comparison tools use this seam without a new shared switch.
