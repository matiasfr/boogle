## Design

All descriptors, preview clocks, camera state, diagnostic buffers and capture metadata are **Local**, owned by the stage document; no sync API, persisted game state, ops or messages change. The existing `renderer.setAnimationLoop` owns sampling after the rendered pose is updated. The existing Buddy adapter remains the authority for retargeted clips and As played body/life layers.

Add a discriminated motion declaration to the catalogue: `none`, authored `clips`, bone `attachment`, or procedural axis rotation with source provenance. Static assets explicitly declare none. For procedural motion, share a side-effect-free rate/formula with its existing game owner where a rate exists; never import a module that starts the game. In particular, current feeder rollers in `src/proto/place/stations.ts:92-104` and `look-kit.ts:244-260` are static instances, so there is no existing angular rate to copy. First inspect the existing feeder transport speed; any diagnostic rotation derived from transport speed/radius must be labelled as a derived inspection motion, not shipped roller animation. If no meaningful game rate exists, report that limitation rather than inventing a production rate. Windmill motion is a time-dependent formula in `src/pois/windmills/index.ts:149`, not merely its 0.55 rad/s base constant.

Expose a typed `assetStage.motion` capture API from `character/main.ts`. Record frame number, monotonic wall time, actual stage/clip time, camera, and measured values from the live figure after world matrices update. Bone diagnostics retain local quaternions, position and root translation; shortest quaternion angles avoid sign-flip false positives. Compare adjacent frames and explicitly label cycle wraps/endpoint discontinuities. Attachments retain their transform relative to the named bone plus distance to the actual posed body mesh; use skinned vertex positions where applicable, excluding hidden wear parts, and disclose any vertex/triangle sampling limit. Distances alone do not prove absence of triangle intersections. Rotating parts retain angular velocity and pivot/axis drift. Report individual outliers with source frame numbers, thresholds and units; never a quality score or accepted status.

Use the existing broker's supported `--eval`, `--action`, `--real`, `--video`, `--frames` and `--seconds`. The already-running trusted broker cannot pick up worktree harness edits. A reusable eval mounts the same-origin stage iframe and awaits its ready/WebGPU/frame counters; an action starts stage sampling at speed 1, fixed camera, turntable off, and emits stage-owned JSON using an uppercase console prefix that the existing harness already logs. A small command orchestrates existing `see-client.ts look` (brokered) or `look.ts` (local), reads its output, and packages stage data plus existing video artifacts. Do not mislabel the legacy background game's `--curves` output as stage curves.

Capture twelve consecutive canvas images immediately after completed stage renders at normal wall time, with frame IDs/timestamps, plus twelve lower-rate images over the full cycle. Use the existing sheet/video tooling to assemble those images, and ffmpeg to retain a supplementary consecutive encoded-video-frame sheet. Encoded frames can repeat/drop presentation frames: report duplicates/gaps and do not claim they map one-to-one to stage renders. Retain the real-time video and frame-indexed numeric JSON/CSV with outlier report. Include all supplemental artifacts beside the broker manifest for launcher handoff, with source fingerprint and exact capture options. Measure canvas extraction overhead; normal clock progression does not by itself prove unperturbed display performance.

## Risks

- Heavy per-frame closest-surface work can itself disturb playback. Cache topology and reusable buffers, bound/disclose approximation, and retain frame timing; do not infer display smoothness from a throttled diagnostic capture.
- The recording is real wall time, but encoded-video cadence is not GPU presentation. Stage frame IDs and times establish capture continuity; Codex cannot judge real-time display feel.
- Loop restart may reset procedural life/attachment state. Separate actual clip seam from As played reset behavior and compare against the accepted Buddy control.
- Background-game health does not establish stage health. Assert stage WebGPU, advancing completed render counters and populated live measurements independently.
- No lockstep, room, transport or save changes are intended; mixed-build/room-safety changes are unnecessary. Do not touch sim math merely to obtain a cosmetic inspection rate.
- `npm run inflight` was already run by the root agent; listed older branches include shared tooling and prototype files. Keep scope to this worktree and do not alter other agents' work.
