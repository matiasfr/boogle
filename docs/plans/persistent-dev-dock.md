# Persistent Dev dock and free camera

Owner-approved implementation brief, 3 November 2026. The approved research commit `8f88c1d4` was cherry-picked as `b301e6ef`. This plan makes that brief concrete; it adds no approval gate or scope. It serves **Understandable at a glance**, **Show, don't tell**, **Small and readable**, and **Pick how each feature shares state**.

## Goal

Keep deliberately enabled Dev available across visits, with its eight tools in an unobstructive dock and a free camera whose lifetime is independent of the panel. Let the owner inspect the same saved Water appearance on the starting area and both home islands without moving an avatar through camera commands.

## Design

- **Local:** Dev enablement, dock position/collapse, bounded camera bookmarks, camera speed, Water preview settings, selected tool and input capture. No network fields, messages, ops, world state or server changes. Enablement is origin-local and independent of build/room; camera-active and fixture authority are never persisted. Each tab owns its own UI/camera; friends continue seeing the ordinary avatar at its physical location, subject to ordinary physics.
- Keep a tiny import-free preference helper outside `src/debug/` (for example `src/dev-preferences.ts`) and the tiny `src/features/dev-menu.ts` lazy gate. Explicit `dev=0` wins; `dev=1` records opt-in. Catch unavailable storage. Validate versioned settings by supported fields, discard invalid fields, and retain enablement across builds. Off clears exact Dev-owned keys plus the existing Water preview key, never game/identity/room saves. Strip debug/tuning flags before reload; reload is allowed for instruments without teardown.
- Replace Pause-hosted shell with an entity-owned strip/dock in `src/debug/dev-menu.ts` and its CSS. Strip: DEV, build ID, Free cam/Return, Report, Tools, Off. Desktop left/right/bottom and collapse; short bottom sheet on narrow/coarse layouts, safe-area padding and 44 px controls. Camera controls remain outside the sheet. Pause may offer an entry that closes Pause without reacquiring lock and opens the dock.
- Keep lazy per-tool descriptors and shared `run`/snapshot history. Export a small typed `registerDockPanel({id,label,load})` registration seam rather than a grade-specific interface. Each selected tool gets a parent and returns a disposer. Dispose samplers on hide/switch; camera is a separate session controller, and Water appearance survives panel disposal. `close()` means collapse the dock, not Return.
- Add a narrow Local input-ownership leaf in `src/player/` for free camera/dock focus. The input and gamepad owners consult it before avatar input and lock acquisition; pause's pointer-lock exit handler distinguishes an intentional Dev release. No feature imports another feature, no new import cycle or registry suppression. Dock typing/dragging consumes game input while retaining native range/text behavior; focus/drag exit releases capture. Free camera owns input until Return even while panels change. Blur/visibility loss clears held camera keys, touch holds and drag state.
- Rework `src/debug/dev/camera.ts` into session camera start/return/update plus a tool view. Preserve and restore position/quaternion/FOV; reuse the entity loop, no second renderer/RAF. Camera pose never writes `me.body`. Mouse/touch scene drag, WASD, up/down, held touch movement buttons, pad sticks and speed are bounded. Use contextual `onKey`/guide rows for camera keys; no new global action or permanent pad slot is needed for panel buttons. Registry checked: core has free slots; retain at least one for updates. Contextual pad sticks and existing buttons are captured only in camera mode. Pause takes precedence over camera controls. Preserve `window.__debugCam` harness compatibility and make overlapping camera ownership explicit.
- Reuse existing island routing: Starting area uses place/default; Lower home uses `classic=1&island=low&room=island-low`; Current home uses `classic=1` without low/place flags. Build links from a bounded appearance flag set, keeping Dev and tuning but dropping fixture/setup/disposable authority. Label all as separate pages with reload. Shore buttons add a bounded camera-only destination consumed after startup; never grant player teleport in normal rooms.
- Water changes remain small: embedding copy and cleanup options only, tolerant restoration of supported saved values, and a clear Play/Get mouse route. Existing compiled-uniform requirement and local-only bindings remain. Remove standalone tuning's indefinite `canLock=false` trade-off; share the same explicit cursor/play behavior. Grade comparison and bloom controls are out of scope.

## Risks and boundaries

- Current camera requires `mounted && modalOpen()` and restores on panel cleanup; both must change together. Current Water cleanup restores all uniforms: hiding the panel must retain appearance without leaving sampling work running.
- Pause currently auto-opens whenever lock is released; opening the dock or starting camera must not accidentally create its backdrop. Conversely Return/Off must restore gameplay lock eligibility without automatically taking the pointer from a slider.
- `releaseInput()` alone in a late-update camera hook is too late: gamepad/actions may already have run. Block at input ownership, then release held actions on transitions.
- Camera and screenshot entity orders, lazy imports, and debug harness override must remain compatible; do not introduce eager debug dependencies or new loop suppression debt.
- Preserve disposable fixture capabilities exactly. No arbitrary shared movement, body mutation, grants, stage skips, save changes or direct world writes. No wire changes or namespace bump.
- `npm run inflight` ran before planning; listed overlaps concern the cherry-picked research index, not current source files. User also identified a concurrent bloom track in Water: keep that file's patch small and do not reformat/rewrite unrelated controls.
- Local storage is untrusted and optional; bounded finite bookmarks and known settings only. Off affects Dev preferences on this origin, not unrelated saves. Physical iPad/pad and real-time smoothness remain unverified unless actually observed.
