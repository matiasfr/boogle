*Plan, 2026-10-31. Source: [brief 10](../research/0.1/10-groundwork.md) §2–4, with the calls in
[SETTLED.md](../research/0.1/SETTLED.md), [brief 7](../research/0.1/7-resource-loop.md) (loop A),

briefs say "v2"; it ships as 0.1. Scope: the systems, with placeholder visuals. Testbed: three work sites from the court
toward the lighthouse, with the home palms as log sources.*

Decisions already taken (owner, 2026-10-31): identity (a) with the Web Lock guard; no transfer or recovery codes yet;
no "forget me" yet; the stack in Lockstep per room; a clean break through a namespace bump; leftover stack pours into
the last site at an age change; spam is bounded by state checks only.

## Order and shape

One commit per milestone on `claude/0.1-groundwork`, each green on `npm run check` (`check:full` after M1, M2, M4, M5,
M8). Final `RULES`:

```
[mushrooms, gifts, roster, stacks, piles, sites, sources, bank]
```

Rules that credit a stack (`piles`, `sources`, `sites`) come after `stacks`, so they call its API inside their own
`apply`. `sites` exposes `onSectionDone(fn)` for `sources` (later in the list) to subscribe to. Since nothing between
M1 and M9 ships on its own, M4 inserts `stacks` before `piles` in the branch; `main` only ever sees the final order.

Every new state starts at `version: 0` with an empty `migrate`; its shape is pinned by the registry check from the
moment it reaches `main`. Mixed builds after this lands: additive only, as before.

## M2. Stable pid + roster (Designed for drop-in, drop-out; Communal world, personal rewards)

- `src/player/identity.js` (new) owns the pid source: `boogle.pid` (10 chars `[a-z0-9]` from
  `crypto.getRandomValues`), the Web Lock guard, the session guest fallback and `adoptPid(pid)` for a later account or
  transfer code. `identity` resolves before the room connects.
- `src/world/sync.js`:
  - `setPid(pid)`; `w:id {u}` is sent in `becomeClient` before `w:need`, by a new host in `becomeHost`, and by a client
    whenever it re-pins the host (a migration). Every tab records `selfId → pid` for every sender, so a promoted host
    already knows the room. The snapshot payload also carries the host's map (`ids`), so a late joiner that is promoted
    later knows the peers that joined before it.
  - `stamp` sets `e.u` from that map (its own pid for its own edits) and never from the edit. An edit from a peer with
    no known pid is rejected. `p` stays the session id.
  - The stale "2-tick per-player op rate limit" comment at the old line 51 is fixed (there is none; state checks bound
    the new ops).
- `src/sim/roster.js` + `rules/roster.js`: op `who.set {n, c}`; state `[[pid, name, c], …]` in index order (dense
  Uint16 index by first sight, cap 256). API `indexOf(pid)`, `ensure(pid)` (apply only), `nameOf(idx)`, `colorOf(idx)`.
  Names are sanitized like the lobby's. `who.set` is rejected when nothing changes (a state check, not a rate limit).
- `src/features/identity.js`: presence `u` (the pid), `who.set` on Jump in and whenever the roster disagrees with this
  tab's name or colour (at most every 3 s), and the "second tab: playing as a guest" note.
- Tests: `test/roster.test.mjs`; `world-sync`: the host ignores a client's `u`, `u` survives a host migration, a peer
  that sent no `w:id` is rejected; `dev/peer-test`: pid binding across three real pages and a host crash.
- Risks: the `w:id`/first-edit race (same reliable channel, sent first); a promoted late joiner (covered by `ids`).

## Identity: now and later

**Now.** A random pid in localStorage (`boogle.pid`), the existing name and colour, and no sign-up. The host binds the
pid to the session over a reliable `w:id` and stamps it on every edit (`e.u`), exactly as it stamps `p`. A second tab in
the same browser can't take the `boogle.pid` Web Lock, so it plays as a guest with a per-tab pid in sessionStorage and
says so. One module, `src/player/identity.js`, owns where the pid comes from.

**What the research says.**
- Anonymous-first, upgrade later is the standard pattern: Firebase signs a player in anonymously, and linking a real
  credential later keeps the same user id and its data (`linkWithCredential`); a credential already used by another
  account fails with `credential-already-in-use`, so a merge needs its own rule
  ([Firebase, anonymous auth](https://firebase.google.com/docs/auth/flutter/anonymous-auth)). Firebase's Identity
  Platform even deletes anonymous accounts older than 30 days unless linked
  ([same](https://firebase.google.cn/docs/auth/cpp/anonymous-auth?hl=en)). Boogle's version: an account adopts the
  existing pid (`adoptPid`) instead of minting a new one, so plaques and tiers carry over.
- Script-writable storage is not forever. Safari's ITP caps localStorage, IndexedDB and sessionStorage at seven days of
  Safari use without a visit to the site; home-screen web apps have their own counter
  ([Didomi summary of WebKit's change](https://docs.didomi.io/releases-and-announcements/announcements/apple-implements-7-day-cap-on-script-writable-storage),
  [iTnews](https://www.itnews.com.au/news/apple-cops-flak-for-deleting-local-browser-storage-after-7-days-539833)).
  A friend on Safari who skips a week becomes a new player. Their old plaque lines stay under their old name; only the
  tier restarts. That is the first trigger for the transfer code (brief 10 §2.2 (b)).
- Web Locks: `navigator.locks.request(name, { ifAvailable: true }, cb)` hands `cb` null instead of waiting when another
  tab holds the lock; widely available since March 2022
  ([MDN, LockManager.request](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request)). Where it's missing
  (an insecure context), every tab is primary: two avatars, one stack, as brief 10 option (b).

**Later, in order.** (1) A transfer code or QR in the pause view that calls `adoptPid` on another device (half a day,
when someone asks). (2) `navigator.storage.persist()` on Jump in, to ask the browser not to evict. (3) Accounts only
with the server as host (brief 10 §2.2, `docs/plans/server-host.md`): a browser host can't keep a signing secret, so
the server would sign tokens whose subject is the existing pid. (4) "Forget me" (an op that blanks a roster name)
before any public room.

## Deviations from brief 10

- `pile.drop {i, j, n}` from your own stack replaces `stack.spill`; the kind comes from the stack, not the edit.
- The route is a pure JS module (`src/sim/route.js`), since rules may only import `src/sim/`.
- The age advances when its sections are done (placeholder for discoveries), so decision 7 has something to fire on.
- Rarity (brief 9 §4.1) is not in the stack yet; it lands as a `version` 1 of `stacks`.
- `bank.wake` is a `hostOnly` op instead of brief 10's env guard (`hostSelf`, `gapMs`).
- Sources store charges spent (absent = full) rather than an array sized to the layout, so validate never sizes state.
