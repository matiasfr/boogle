# Dev menu, first version

_3 November 2026. Implementation plan for the owner's approved [research](../research/dev-menu-plan.md), including its Hard rules and eight numbered decisions. The owner's current brief approves this plan within those limits. No further approval stop is needed; an excluded-path change or registry debt is omitted and reported instead._

## Goal

Open Pause → Dev with `?dev=1`, reach a mechanic in a disposable test run, inspect it, and share a reproducible setup. Serve **Toys before chores**, **Clear authority**, and **Small and readable**. This is not player fast travel, resource grants, or a second simulation.

## Design and boundaries

- Menu, camera, water appearance, overlays, measurements, reports, setup settings and command history are **Local**. They send no new messages or edits. The existing player body is **Owner** state; moving it is permitted only by the new disposable-run predicate. No remote body, Host state or Lockstep state is directly assigned.
- Place scenario setup uses its existing **prototype-local** stage handlers only with `proto=place&coop=0` in a fresh, explicitly launched disposable run. It does not claim server capability, privacy or access control. Place co-op authority remains distinct from room lead and server authority.
- Do not edit `src/net*`, `src/world/`, `src/sim/` or `server/`. Do not grow suppressions, cycle lists, service allow-lists or registry debt. Read-only imports of existing diagnostics are allowed. No new wire shapes, ops, saved world schema or namespace change.
- Reuse Pause's existing `pause` action (Menu pad slot, Escape/H, touch Menu). Do not allocate a new action or pad slot. Its modal captures gameplay keys while editing. UI rows and tool controls are at least 44 CSS px, with safe-area spacing and visible Back/Resume controls.
- A tiny `src/features/dev-menu.ts` checks the exact query value `dev=1`. Without it, no Dev module import, CSS, DOM, entity, timer, frame hook, GPU readback or network message exists. With it, register the pause page; dynamically import each tool when opened or commanded. Tool-owned descriptors contain `id`, label, scope, availability/reason, bounded arguments, command handler and dispose. No central action switch grows with tools.
- Share the pause-page seam through `src/player/pause-pages.ts`, not an import from one feature into another. `src/features/pause.ts` renders registered pages and calls their cleanup on navigation, close and native dialog close. The shell is loaded only behind the gate. Reject late async mounts after disposal.
- Expose a typed optional `boogle.dev` in `src/globals.d.ts`: `tools()`, `open(tool?)`, `run(tool, command, args?)`, `snapshot()`, `close()`. UI calls the same `run` path. Results are bounded plain JSON (`ok`, reason/message, optional data); keep the last 40 results. No eval/property setter API. The API permits production-build broker checks without importing `/src`.

### Disposable launch and setup links

`src/debug/dev/fixtures.ts` owns the fixture version, exact run marker, launcher and predicate. A one-click Start button creates `crypto.randomUUID()`, a fresh room name, and a matching sessionStorage launch record; navigate to a same-origin allow-listed URL with `dev=1&proto=place&coop=0&fresh=1`, fixture version/id and selected scenario/destination. Preserve only approved appearance flags. Store no user credentials and import no saves. Existing `job.ts` already scopes solo saves to `boogle-place-v4:<room>`; do not call `forgetSaves()` (it clears all place saves), `localStorage.clear()` or legacy Start over.

Every mutation checks the same predicate at execution time: supported version, matching session launch record and exact room, explicit solo place route, initialized player/place adapter, no other peers. A `proto-` prefix is never enough. Mark the session visibly TEST for its entire visit and mark debug intervention in its report/telemetry. A joined peer disables mutations; it does not authorize a shared skip. Restart creates another fresh run, or asks with the current run's name before any same-run reset.

Setup links contain only allow-listed version/build, route, named destination/scenario and bounded Local settings. They do not contain the active launch marker or room credentials. Opening one shows the proposed setup and a Start disposable run action; it never executes a skip or resets the joined room. Unsupported version/settings receive reasons; a different build warns that this is a setup, not exact world replay.

### The eight tools

1. **Water** (`src/debug/dev/water.ts`). Reuse `src/debug/water-tuning.ts` and retain the standalone `src/features/water-tuning.ts` route. Extend `showWaterTuning` with an optional mounting parent and a returned disposer, preserving existing callers. Mount inside the dialog so the browser top layer does not hide it. Its entity, style, subscriptions and input ownership dispose on close. Avoid duplicate mounts when `tune=1` already opened the standalone panel; the Dev host can take over/close that instance. The shipped `src/render/water/live.ts` builds uniforms only when `water=new&tune=1` existed at load. Therefore offer **Reload with tuning** and explain this load-time requirement when missing; do not pretend opening the panel can convert constants to uniforms. No renderer changes are needed. Make all mounted inputs, summaries and buttons touch-sized. Existing appearance controls are Local; no body/floater controls are added.
2. **Go to** (`src/debug/dev/destinations.ts`, `src/debug/dev/place.ts`). Named places: spawn, shore, shallow water, deep water, big-fall plunge, tower, Far Head, forge, current construction frame and Return. Derive place coordinates from `layout.ts`, `terrain.ts`/`land.ts`, `run.activeFrame()`, tower definitions and current route; water-demo camera views remain camera-only. Include sensible home-island camera bookmarks based on its spawn/terrain/coast. The hard rule specifies a place fixture, so home player teleport is explicitly unavailable: the one-click button starts the corresponding place test. Do not invent a second home fixture contract.

   Store a Return pose before the first successful Go to, retain it across subsequent hops, validate it again on return. Named landings are finite and within route bounds, query actual static floor/deck support with the existing physics facade, reject steep/obstructed/unsupported landings and offset feet by `PLAYER_R` plus clearance. Water targets require an actual sea region and sufficient depth; big fall is a deliberately labelled airborne pose above the verified deep-water target. Never silently advance progression to make a destination usable; offer a camera view if physical access is unsafe.

   Before moving, release input/jump/throw, close glide/cancel hook, call place `standUp()`, detach platform carry including `x/y/z/spin/on`, and use existing safe held-object release paths. If a carried/pair/vehicle state lacks a safe detach API, refuse with **Put it down / get out first**, rather than mutate its ownership. Use `teleport()` and clear linear/angular velocity, wish/jump state and cached player water query. No destination can receive arbitrary user coordinates.
3. **Free camera** (`src/debug/dev/camera.ts`, `src/debug/debug-cam.ts`). Preserve `window.__debugCam.set/clear` for the harness; fix restoration of FOV and use an entity-owned late camera override instead of adding an `onFrame` registration/debt. Bounded movement, named bookmarks and a captured return pose/FOV. Camera bookmarks never teleport the player. The modal continues capturing player movement/interactions while camera UI receives drag, directional/up/down controls and pad sticks. Read the connected pad only in the active camera entity, or forward axes through the existing modal seam without a new gameplay action. One-click Return, Back, Resume and native close restore overrides, pointer state and input. No camera entity/frame work remains after close. Keep the game/server running.
4. **Inspect** (`src/debug/dev/inspect.ts`). Read `inspect()`, `waterRuntime.inspect()`, the synchronous `waterField.nearby()` result and an explicit place adapter (stage/current frame/seat/carry). Show query validity/age and legacy/unavailable labels. A visible-only sampler and optional entity-owned nearby collider/deck outlines/water-region readout are bounded by distance/count. Use `forEachStatic` and actual physics data, not scene-graph game state. Do not turn on GPU field readback implicitly. Dispose geometry/materials/entities and subscriptions on close; no full-scene outline dump.
5. **Performance and startup** (`src/debug/dev/performance.ts`). Lazy reuse `hardwareTiming()`/existing profiler data with Measure and Copy; preserve unavailable GPU timestamps and actual-presentation limitations. Full profiling has a flagged reload because GPU timestamp capability is chosen during renderer creation. Existing profiler/startup instrumentation without teardown remains explicitly reload-enabled/disabled; do not import `netdebug` or an old profiler UI merely to show a Dev readout. Offer Reload with `prof=1`, Reload with `startup=1` (optional existing video flag), inspect/copy the existing startup snapshot when available, and Reload without capture. Explain that reload cannot prove a cold Metal cache. Optional recording stays the existing `record=1` launch/API and is labelled input trace, not a world rewind.
6. **Room health** (`src/debug/dev/room.ts`). Read `worldStatus()`, `net.room`, `getRoomId()`, existing builds diagnostics and place co-op status. Show server connection/transport, lead, local/remote build IDs, queued/dropped/rejected status when actually exposed, hash counters/latest result, and separately place authority/follower state. Unknown or unsupported data is labelled unavailable. Do not import `netdebug.ts` directly: it installs permanent callbacks, timers and desync request messages. Adapt its read-only status formatting/data instead. No snapshot load, send, reset or mutation buttons.
7. **Report** (`src/debug/dev/report.ts`). Copy JSON with BUILD, WORLD_NS, schema/fixture version, effective `pageQuery()` flags, route, available tool settings, player/camera pose, fixture identifier, inspection summary, measured performance and recent bounded command results. Include a setup URL; select/download fallback handles denied clipboard access. Screenshot captures the existing renderer canvas as PNG and reports explicit failure if browser capture is unavailable; no second renderer. UI identifies canvas-only capture. Offer optional existing record controls when available, otherwise its flagged reload. Revoke temporary object URLs.
8. **Test scenarios** (fixture module plus `src/debug/dev/scenarios.ts`). Named fresh-run stages wrap existing place handlers: fresh, walk/current frame, first path, line 2/forge, tower, Far Head and trains (Q5 only if useful as the existing named fixture). No item grants, money/score/crystal controls, arbitrary restore, resource fields or generic skip commands. Export/use a narrow typed scenario adapter from `src/proto/place/panel.ts`; keep existing harness globals intact. Execution goes through the disposable predicate even when invoked through `boogle.dev`. Keep the TEST badge visible after closing Pause.

## Production evidence

Use the already-running broker, never direct Chromium. No source edits while a run is in progress. The parent owns final full QA; implementation should expose the bounded command API to make each behavior inspectable on the production build.

Visual question: **Can a tester on desktop and a 390 px phone reach a named water/mechanics test, see TEST/local scope and Return, and keep all controls usable without affecting the joined room?**

- `node .look/see-client.ts look --production --query 'dev=1&water=new&tune=1' …`: open Dev, open/use all eight tools, inspect desktop layout, tuning host and report fallback. Use `--eval`/`--action` through the UI/API and capture completed frames.
- Launch a disposable scenario through the actual launcher, verify TEST, shore → Return, free camera movement/bookmark → Return and restored FOV. Copy report, download screenshot, reopen its setup URL and verify that setup waits for an explicit launch. Record a shared-room scenario/teleport refusal and unchanged state; also inspect mixed-build reporting with two clients using the existing harness.
- `node .look/see-client.ts look --production --size 390x844 …`: verify scroll, 44 px target bounding boxes, visible Back/Resume, no horizontal overflow and no game actions while typing. This is phone-width browser evidence; real phone/iPad touch and real-time feel remain unverified.
- Dev-off production capture: compare resource entries, style/DOM selectors, `boogle.dev` absence and entity inspection. No Dev chunk, CSS, sampler or entity/frame hook may be present. Legacy explicitly flagged diagnostics are baseline, not an off-cost failure.
- `node .look/see-client.ts playthrough --production`: run the full place bot once, read its report even if it fails, list checkpoint names with `look --at list`, inspect relevant checkpoint/end PNGs with `view_image`.
- Use only existing trusted `scenario world-inputs` named scenarios if the implementation changes an existing sync/input contract and that scenario is relevant. No new harness. Use curves/consecutive frames for motion evidence and label real-time feel unverified.

Every successful command is execution evidence, not a visual verdict. Open the saved PNGs, record what answers the visual question, iterate at most three rounds, and link exact-tree manifests. The final report is under about 150 words with result first, the full query, check/bot outcomes, opened images/observations, limitations and the required fenced JSON.

## Risks and resolved limits

- Pause is an existing feature hotspot; add only the reusable page seam and lifecycle handling, no alternate modal system. Water currently appends outside the dialog and has no public disposer; both must be fixed for an embedded panel.
- Existing debug camera changes FOV without restoring it. The Dev tool must restore it on every exit, and asynchronous tool completion must not resurrect disposed UI.
- Place has broad mutable legacy globals and skips. The new API exposes a narrow adapter only, repeats the fixture gate at execution and never treats `proto-` or `coop=0` alone as authorization. This contains new behavior; it does not certify legacy globals.
- Safe detach is more than zeroing velocity: seat, platform, hook/glide, hand and pair/vehicle state must be resolved or refused. A failed destination leaves the player and Return pose unchanged.
- Home-equivalent bookmarks are available; home player cheats are omitted because the approved fixture hard rule explicitly requires `proto=place&coop=0`. The UI offers one-click corresponding place tests. This respects, rather than changes, the hard rule.
- Runtime tooling is Local and not deterministic sim code. It does not introduce new Lockstep math or schema. GPU query/presentation unavailability and warm-cache uncertainty must survive reports as explicit unknowns.
- `npm run inflight` was attempted by the planner but sandbox-blocked on FETCH_HEAD; the parent reports its required invocation returned a branch list. Do not repeat fetch-capable commands under the user's local-only network restriction.
