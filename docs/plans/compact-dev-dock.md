# Compact Dev dock

Owner-approved follow-up to [persistent Dev dock](persistent-dev-dock.md), after the `origin/main` merge at `5d292bbc`. **Proceed within existing scope:** this records the requested UI revision, not a new approval gate. Serves **Understandable at a glance**, **Show, don't tell**, and **Small and readable**. Parent owns the separate sky decision in `docs/proposals/boogle-2.md`.

## Goal and design

Make one selected tool quick to reach and small enough to tune while watching the scene. At 1440×900, the desktop side dock is at most 300 CSS px wide; phone/coarse-pointer remains a short bottom sheet with safe areas and 44 px targets.

All new UI state is **Local**: selected tab, Water search, pinned individual controls and open groups. Reuse the existing bounded tool commands, camera session, lazy panel registration and input capture. No new controls-registry actions, pad slots, wire fields, ops, renderer bindings or authority. Preserve current camera/bookmark/Return behavior, opt-in/Off semantics and disposable movement/stage restrictions. A friend sees no UI/settings changes.

Keep AgX look selection, bloom checkbox/numeric binding semantics and sky controls exactly functional as merged. Layout/search/reset changes must not alter values, defaults, shader paths or validation. Unsupported saved appearance values still drop; explicitly pasted appearance JSON stays strict.

## Risks and acceptance

- A compact UI cannot hide safety: Local scope, reload destinations, unavailable tools and disposable mutation limits stay clear. No always-expanded duplicate headings, scope paragraphs or islands in every panel.
- Preserve native pointer/range/text behavior and the existing dock input capture. Free cam persists through tab changes, and slider/search input must not move or interact with the avatar. Keep touch targets 44 px even if fine-pointer desktop rows are denser.
- Search-driven expansion must not overwrite explicit open-group preferences; filtering must not remove a focused control while dragging. Async tool loads still cancel stale mounts and dispose samplers.
- Existing `water-tuning.ts` contains both tolerant saved validation and merged checkbox flags; preserve both. Do not rewrite controls or render bindings as part of presentation work.
- Scope is UI refinement within the approved feature. No game flow, sky/tone/default changes, new camera mechanic or fixture permission expansion. Real-device feel and real-time smoothness remain unverified unless actually observed.
