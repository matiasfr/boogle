# Post-look real-render comparison

## Goal

Implement the eight ranked recipes in [low-poly-post-looks](../research/low-poly-post-looks.md), subject to its coverage and AO gates, as independent Local Dev Looks layers. Deliver matched real-render PNG sheets so the owner can choose inviting toys and distant scenery while retaining rich water. Serves **Show, don't tell**, **Telegraph everything**, and **Small and readable**. This is an authorized comparison, not a production look change or a new gameplay prototype.

## Design

- All appearance controls, mask allocation, capture cameras and performance switches are **Local**. Extend the existing `looks.ts` lazy import and Dev Looks descriptor; no network, ops, presence, persisted world state or lockstep math changes. The only persistence is versioned Dev preview settings. Existing disposable fixture gates retain authority over player movement/staging.
- Ordinary pages retain the existing `installWaterPost()` graph, Neutral, trim 1, meter, stored 4× MSAA, procedural `.24` sky and current water. Put candidate graph builders behind the existing `tuningEnabled` dynamic import in `post.prepare()`. Do not statically import a candidate/mask/AO/filter module into the production path.
- Keep existing five tone/water presets compatible. Add a separate layer configuration and named A–H recipes; selecting a recipe uses Current/trim 1 and unchanged water. Expose independent toggles/strengths plus settings JSON and explicit gate reasons in the existing panel. Preserve explicit Graphics overrides; do not silently force a saved bloom override. Capture setup explicitly clears conflicting overrides and logs effective values.
- Add one dev-only boolean Graphics switch, `postLooks`, whose on state applies the selected layer configuration and whose off state uses the original output, original fog and no optional attachment updates. Register it only from lazy comparison code. Use `measureGraphics('postLooks', …)` for each selected column, reusing the established ABBA owner; do not build another timer. Bloom belongs to the existing chain. Report recipe E against A with its whole combination restored correctly in both states.
- Structural toggles rebuild/cache graph variants and prewarm before timed captures; parameter edits use uniforms. Off must disconnect the optional graph and MRT, not merely multiply its result by zero. Retained allocations are acceptable if their draws/copies/updates cease and this is disclosed.
- A single generic shared-class coverage policy is the mask strategy, not per-asset opt-in. `MRTNode` in installed r187 has per-attachment blend modes/clear colors; `NodeMaterial` merges material MRT outputs and supports builder context. A shared TSL `Fn((args, builder) => …)` may classify `builder.object`/`builder.material` at build time: normal opaque→R, actual ocean→G, all sprites/translucent overlays and depth-writing marine snow→B, background→zero. Pass the ocean material/object identity to the lazy owner; do not guess water from hue or world height. Preserve alpha/alpha-test/alpha-to-coverage and outgoing alpha, and use independent mask blending instead of inheriting ocean color blending. Verify custom `fragmentNode` paths separately: those bypass ordinary `NodeMaterial` MRT merging. No cached material mutation, parallel material library or asset clones.
- Resolve the RGBA8 mask with scene MSAA. Require R>.98 at eligible centres, reject G/B and dilate their exclusion by 2 output pixels. Ink allows sky/background neighbours for silhouettes. Use scene-texel-centred depth reads; support at least one scene texel at `.6` scale and attenuate opacity by scene/output scale. Reuse underwater's existing signed camera-depth node (positive submerged), exposing it as a read-only return value if necessary. Never substitute the coarse lens grid for full-resolution surface coverage.
- Recipe haze extends the current fog factor before its existing mix. `frozen-sky.ts` owns directional scene fog; `water-render.ts` passes the surface fog callback to `surface.ts`. Share the bounded height-fog expression at these two seams; preserve default expressions when comparison is absent. Use surface world height, not refracted bed, and record the existing fog-disabled soft-particle mismatch.

## Risks and gates

- MRT correctness is the highest risk: custom fragment outputs, transparent blend/alpha, depth-writing snow, label coverage and stored MSAA must be observed, not assumed. A dark line over refracted bed is a failure even when it looks plausible.
- Post ink must bypass near submersion because underwater/lens distortion uses different UVs. Live water phases will not be pixel-identical across reloads; preserve controlled timing where possible and label residual differences.
- Fog changes touch shared rendering owners; no change to normal-player shader expressions or default first-load imports is acceptable. Avoid replacing source APIs just to make an experiment convenient.
- No room-safety, wire or save changes are planned. No world-state grants or teleport outside existing disposable fixture authority. Parent attempted `inflight`, which failed on protected Git metadata; remote retry is prohibited by the owner's local-network-only instruction.
- The research AO revisit gate is unresolved until baseline T/B inspection. It is not a default permission to implement AO.
- Changes are not an adopted style. Stop after evidence and owner choice; no additional gameplay or terrain work.

## Open questions

None blocks the authorized comparison. Coverage feasibility, AO benefit and exact current anchors are implementation/evidence questions. The only owner choice at delivery is: **which makes the toys and distant world feel more inviting while the sea still feels rich?**
