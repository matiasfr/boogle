# Asset author

Use the existing builder and asset stage. Passing checks is not art approval. No paid Meshy generation without the owner confirming the model and cost. Do not copy third-party skill text unless its licence and notices are preserved.

**Image references first (owner, 5 November):** before modelling, capture the real game, make a screenshot-based previz, then a front, side and back sheet via concept-art, plus close-ups of the parts that carry the asset's character. The in-game silhouette alone isn't enough to model details from. Record reference roles and unresolved cross-view contradictions; images are not dimension measurements. For a requested text-only comparison, freeze that brief before revealing the concept and hold build/repair budgets and stage framing equal. Inspect both actual GLBs before claiming the reference helped. If generation is blocked, report the missing route/access and leave the comparison unanswered. [Experiment](../../../docs/research/motion-references.md).

1. **Measure the brief.** Use [the brief/evidence reference](references/workflow.md). Separate measured dimensions (source/landmark) from inferred choices; specify silhouette, named parts, metre/game-axis convention, pivot/socket or bone/rest contract, budgets, intended motion and forbidden detail. Follow the existing [art-kit guidance](../../../docs/research/art-kit-pipeline.md); keep broad toy-like surfaces and Buddy's readability.
2. **Make one canonical recipe.** For a requested dry exercise, use the `.look/` scratch-build recipe in the reference. Production source is `assets/src/<id>.py`, with revision parameters in the same-stem JSON or clearly named constants. Name parts and pivots; document `(x,y,z)` game → `(x,-z,y)` Blender conversion and Y-up export. See the parameterised roller example in the reference. Do not let hand edits become a second source. Start with named primitive silhouettes, no tiny detail; inspect front/side/back/three-quarter blockout before detail.
3. **Build, then inspect.** `npm run assets -- <id>`; use existing catalogue registration for production. Run `node dev/assets/inspect.ts assets/built/<id>.glb .look/<revision> <ortho-metres> <centre-x,y,z>`. Parent directory must exist; output directory must be new. Run Blender outside Codex's sandbox (sandboxed startup crashed in the trial). Size targets (4 MB per asset, 2048 px textures, 25 MB first load, 100 MB total) only warn in the build and `--check`; they never fail it. Open all four views in each clay/part-colour/wire/material row; the helper's material row is Workbench colour, **not final game shading**. Read decoded reimport metrics, compare exported/evaluated triangles, materials, world bounds, normals, degenerates, connected parts and solid/open-surface exceptions. Retain node transforms: quantization adds decode scales. Builder pruning removes empty sockets; verify exported landmarks rather than assuming empties survive.
4. **Stage against Buddy.** Use the actual built asset in `/character/`, with matched camera, light, exposure and pose/time across revisions; include game distance. Inspect final runtime materials and a turntable, using owned preset clones. For an axle-centred part the floor may hide its lower half: lift the preview holder, never change the asset pivot to repair framing. Attach wearables to the real bone early. Use look/broker captures, open the PNGs and keep their manifests; exact stage examples are in the reference.
5. **Review motion.** Anything that moves, including rigid bone attachments, goes through `dev/look/asset-motion.ts` per [look](../look/SKILL.md#asset-motion-review). Inspect consecutive rendered frames, a full cycle, consecutive encoded-video frames and stage-owned curves/outliers. Compare suspect clips with Buddy Raw Walk_Loop. A diagnostic spin is not a production rate; background player curves say nothing about a stage attachment. Posed-body samples are not exhaustive collision proofs, nor is encoded video proof of display smoothness.
6. **Repair and stop.** Budget one initial result plus **at most two diagnosed repairs**; stop sooner if a repeated repair fails to improve the defect. Before each edit retain recipe, parameters, built GLB, failed media and metrics. Rebuild and recapture affected evidence; keep a cause/change/result/time/cost ledger. `sourceHash` misses imported helpers, builder/preset changes and tool versions: record those dependencies and tree/tool versions alongside source/build hashes. Finish with stage links, what you actually opened, failures and limits, and **one owner question** about the intended silhouette/fit. Stop for their answer; checks never approve the art.

Basis: [model trial](../../../docs/research/asset-model-trial.md), [motion repair](../../../docs/research/asset-motion-review.md), [pipeline feedback](../../../docs/research/agent-model-pipelines.md#feedback-that-catches-the-bad-result). This proof covers small props and rigid attachments, not new skin weights, rigs or characters.
