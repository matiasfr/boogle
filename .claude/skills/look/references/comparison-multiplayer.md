**Before and after: `npm run before-after -- <git ref> [look options]`** runs the same capture on that commit and on this checkout and writes `<name>-before-after.png` side by side (with `--curves`, the plot overlays both). Use it with `--cam`/`--look` or `--at`, so it's one camera and one state. About 16 s.

**Two players: `npm run look -- --players 2 --eval dev/look/evals/railway-job.ts --query 'shot=play' --until window.__placeDone`** (the production route on both; add `&botTo=T2` to the query to stop early, or use `npm run playthrough -- --players 2 --to T2`). Each page has its own browser profile, so neither takes over the other ("You're playing in another tab"); the eval runs concurrently on both with `&player=1` or `2`, their `COOP ...` lines print, and it fails if they never saw each other. Setup and warm-up default to 5x: a disposable server child scales its clocks and timers, and both pages run at the same cap. `--real` opts out; `--warp-speed N` tries another cap. All three return to 1x for captures. The run prints achieved rates, clock deficits, world-tick differences and train positions, saving raw samples in `<name>-warp.json`; a peak clock or world-tick deficit over one game second prints DRIFT, and a deficit still over one second at the end fails the run. A requested speed is not a measured speed. Add `&coopMinutes=3` for three more game minutes of trains. `node dev/codex/see.ts` supports this when the broker's checkout also has the updated look harness; an older broker rejects `--clock-url`. Details and measured limits: `dev/look/README.md`.
